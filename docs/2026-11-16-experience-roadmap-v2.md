## 用户直接干预：产品约定

**入口**：后台 → 子代理会话 → 补充要求。查看与补充是主要动作，停止独立。

**目标**：显示具体子任务及所属主任务，用户不必手工抄 session ID。

**发送**：补充现有任务，不暗中 fork、不重启；下一安全执行点送达，不能承诺立即抢占正在运行的工具。

**回执**：待发送／已排队／已送达／失败来自真实服务状态。「已送达」只说明投递，不等于模型已理解或执行完成。

**来源与协调**：标明来自用户，让子代理和主代理都能追溯内容、目标和状态。回执不自动触发额外模型调用。

**优先级**：建议产品语义：同一任务的明确目标冲突，以用户新要求为准；普通协作继续，不做无依据的全局抢占。

**权限**：用户入口单独鉴权并复用运行机制；不通过伪装主代理身份绕过限制。项目、工具与子代理权限仍有效。

**结束边界**：已结束 Explore 不能在这里自动续跑；显示真实原因并保留用户未发送文本。

**纠正方向**：可用一条明确的补充要求表达；本版不增加名为「立即纠正」却没有中断保证的假按钮。

### A01 · 后台直达子代理，不再翻旧消息

类别：核心主线 ｜ 平台：TUI / GUI ｜ 来源：用户提出
交付勾选：0/6；体验验收：未验证

**用户场景**：主会话已经很长。想看看两个 Explore 各自查到了哪里，却得向上寻找早先混在对话中的任务卡。

**基准现状**：既有审查显示：TUI 后台任务行默认进入终止确认，完成态被设置为只读；后台接口已返回 sessionID／parentSessionID，TUI 已有子会话路由。GUI 已能打开运行中子任务并查看完成结果，不能把它重复立项。

**希望得到**：TUI 右下角「后台」成为稳定的任务导航入口。查看是默认动作，停止是独立动作；查看后可以顺手返回。

交付子项：
- [ ] TUI 后台任务行的鼠标点击／Enter 默认打开对应子代理会话，复用已有会话页面与消息同步。
- [ ] 运行中、已完成、失败、已取消的任务，只要子会话仍存在，都能查看；不因结束状态禁用导航。
- [ ] 终止改为独立的次要动作，保留确认；查看本身不取消任务、不重发请求、不启动新的模型轮次。
- [ ] 从后台进入后，可以使用已有 Parent／同级切换能力；返回主会话时保留草稿与阅读位置。优先复用已有阅读恢复，补齐实际缺口。
- [ ] 列表刷新按稳定任务 ID 保持选择与搜索位置，避免正要点开的条目因排序变化跳走。
- [ ] 子会话失效时就地说明；后台结果已回收但仍持有有效会话 ID 时仍可打开会话。不以 job ID 猜测 session ID。

体验验收：
- 主会话派发两个 Explore，继续工作到原任务卡离开视口；从「后台」进入 A，返回，再进入 B，全程无需翻主对话。
- 运行中实时阅读，完成／失败／取消后重新进入仍可看历史；查看不影响任务运行。
- 带草稿和已上翻阅读位置往返；遇到跨 worktree 子会话时沿用现有工作区路由并核对返回目标。

范围：首版不重写后台调度，也不另造完整日志系统。TUI 是本项主要新增面；GUI 已有任务导航做一致性回归。

### A02 · 后台终端可查看，也能看懂用途

类别：核心主线 ｜ 平台：GUI / TUI ｜ 来源：讨论新增
交付勾选：0/6；体验验收：未验证

**用户场景**：一个 bash 留在电脑上很久。用户能看到 PID，却不知道里面是否还有任务，更不知道关闭会影响什么。

**基准现状**：既有审查显示：GUI 后台列表点击非 job 条目会返回，没有接到终端查看；现有 GUI 终端面板已支持切换与聚焦。PTY 有 command／args／cwd 和缓冲，任务来源与用途仍需按真实发起点补记。

**希望得到**：点击终端默认看输出。常用信息帮助用户判断；终止从「唯一能做的事」变成知情后的选择。

交付子项：
- [ ] GUI 点击后台终端，打开并聚焦已有 PTY；不创建空终端，不重复执行启动命令。
- [ ] TUI 首版提供该终端已有输出的只读查看与返回；完整嵌套交互终端不设为本版前置条件。
- [ ] 详情展示真实启动命令、参数与工作目录；启动的是 bash 就按 bash 展示，不猜测它内部的当前命令。
- [ ] 在能够识别的创建入口补记来源会话／任务和用途；旧记录或来源缺失明确写「未知」，不反推假归属。【可后置增强】
- [ ] 把长期运行／用途标记作为可选增强，由用户明确设置；只因运行久不自动杀进程，未采集的活动时间不伪装成已有字段。【可后置增强】
- [ ] 输出不可用、已退出、上次未正常结束分别说明；查看后能回原面板，终止仍独立确认。

体验验收：
- 启动一个开发服务和一个短命令，从后台分别查看输出与真实命令，能判断哪个应该保留；不借助系统任务管理器。
- 打开运行中的 GUI 终端前后 PTY ID 与进程不变；TUI 查看只读输出不会向进程发送输入。
- 历史记录缺少来源时如实显示；未知归属或孤儿记录不提供可能误杀复用 PID 的操作。

范围：只覆盖 RedCode 已登记的任务／PTY，不扫描并接管所有系统进程。来源采集、用途标记是增强项，不阻塞先把「查看」接通。

### A03 · 用户直接给子代理追加要求

类别：核心主线 ｜ 平台：TUI / GUI ｜ 来源：用户确认方向
交付勾选：0/9；体验验收：未验证

**用户场景**：进入 Explore 后发现它正在查无关目录。用户想说「先别查归档，重点看 data_sync.py」，不该必须退回主代理再转述。

**基准现状**：用户已确认主代理支持追加要求。既有审查中 task_status(message=...) 已有运行中直接子任务的 steering 通道及 queued／delivered 回执；GUI 子会话仍以禁用普通输入、停止与返回为主。现有工具能力不等于用户 UI／授权接口已完成。

**希望得到**：进入子代理后可以「补充要求」，保持观察；用户知道请求到哪里了，主代理知道任务要求发生了什么变化。

交付子项：
- [ ] 在运行中的子会话与任务操作中提供明确的「补充要求」入口；目标名称和所属主任务可辨认，不藏在终止菜单内。
- [ ] 增加面向真实用户的服务入口，复用已有 steering 执行机制；明确鉴权、目标会话与项目归属，不伪装成主代理工具调用。
- [ ] 发送前保留可编辑草稿；发送后展示待发送／已排队／已送达／失败等真实状态，失败保留原文并可重试。
- [ ] 明确「补充」在下一安全执行点生效，不等同于立即打断正在运行的工具；停止／打断如另有能力，应是单独动作。
- [ ] 把人工补充和投递回执作为可追溯记录留在子任务，并让主代理可见；不为通知本身强制启动额外模型轮次。
- [ ] 明确产品语义：对同一任务目标的显式冲突，以用户新要求为准；执行仍受既有项目、工具与子代理权限约束，不增加隐式提权。
- [ ] 区分「已送达」与「已理解／已执行」。只在观察到后续行为或回复时展示执行证据，不把持久化回执当成执行完成。
- [ ] 本版仅介入正在运行且可接受引导的任务；已完成 Explore 不自动续跑，不用普通聊天入口绕开现有续跑限制。
- [ ] 用户返回主会话后能看到刚追加的内容与状态；两端进入／返回时保留各自草稿和阅读位置。

体验验收：
- 运行两个 Explore，用户从后台进入 A，追加「只核查 KH 的同步入口，先别看归档」；A 收到，B 不受影响。
- 投递期间任务仍可继续；送达状态与服务端一致。失败保留原文，用户能重试而不是重新输入。
- 返回主会话，人工补充有来源、有目标、有状态；主代理继续协调时能够获知调整。
- 子任务已经结束、跨项目无权操作或不支持继续时明确说明；不暗中重启、不越权执行。

范围：这是本版核心功能，不降成可有可无的输入框。只做「发出去」而没有真实回执和主代理知情，不算完成。更丰富的暂停／重分配另行评估。

### A04 · 把「引用到输入框」做成通用动作

类别：核心主线 ｜ 平台：GUI / TUI ｜ 来源：讨论新增
交付勾选：0/6；体验验收：未验证

**用户场景**：回答很长，只有一句需要追问；终端里出现报错。用户不想复制、粘贴，再手工解释「我说的是哪一段」。

**基准现状**：文件／Diff 选行评论和 GUI 后台结果引用已有基础。已检查的普通消息、TUI 消息菜单及终端选择主要提供复制等能力，缺少一致的带来源引用流程。

**希望得到**：普通消息、工具输出、终端错误都能直接加入当前草稿；原内容不丢，引用的出处可找回。

交付子项：
- [ ] GUI 普通消息与工具输出选区提供「引用这段」，不必先复制到剪贴板；无选区时明确引用范围。
- [ ] GUI 终端选区也使用相同动作，保留终端名称／来源说明；不能把整份滚屏日志无提示塞入上下文。
- [ ] TUI 首版在消息／工具操作里提供引用入口；复杂选区浮层不是首版前置条件。
- [ ] 引用追加到用户当前草稿，保留原文本、附件与已选配置，不自动发送。
- [ ] 引用保留可追溯的会话／消息／part 或终端来源；可定位来源能返回，不可定位明确说明。
- [ ] 引用长内容时采用明确上限与截断提示，用户能确认将发送的内容；复用现有文件评论／后台引用约定。

体验验收：
- 选中助手一句话并引用，原草稿仍在；用户补一句问题后自行发送，来源可识别。
- 选中终端一段错误引用，不需要手动输入终端名；已存在的附件不丢。
- 连续引用两处内容，来源分别保留；长内容不会默默全部发送，也不冒充完整引用。

范围：先做统一引用，再考虑「让 AI 修复」等快捷语。文件选行评论和后台结果引用已存在，不重复开发；首版不自动花费模型额度。

### A05 · 文档和原型，直接看成品

类别：核心主线 ｜ 平台：GUI ｜ 来源：讨论新增

### A06 · TUI 按轮阅读结果，过程随时可展开

类别：核心主线 ｜ 平台：TUI ｜ 来源：讨论新增
