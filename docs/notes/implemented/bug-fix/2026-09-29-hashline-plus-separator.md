# hashline 的 `+ ` 分隔符语义：补文档示例与回归钉

状态:implemented

## 问题

一次会话内在三个文件上连错三次（`instruction.ts` 两处、`instruction.test.ts` 一处），
症状完全相同：hashline 写进去的每一行都比预期少一个前导空格。`instruction.ts` 里
`truncateToBytes` 函数体写成 1/3/5 空格缩进，`system()` 主块写成 5 空格，
全靠 oxlint 与 typecheck 抓出来，再用脚本按行号补回。

## 根因（不是解析器 bug）

`readBody` 的 `/^\+ ?/`（`tool/edit.ts:457`）严格实现了 `edit.md` 写明的约定：
`+` 之后那个空格是**分隔符**，不属于内容。所以自身以 N 个空格开头的内容行，
需要在 `+` 后放 N+1 个空格。

问题出在文档与容错的组合：

- `edit.md` 通篇只有**非缩进**示例（`+ replacement line 1`），从未演示过缩进行。
  规则写了「`+ `（one space after the plus）」，但没有可照抄的样例。
- 解析器同时容忍不带空格的 `+foo`（0.8.2 修「多写一个前导空格」时的副产品，
  `edit.test.ts:643` 的 `"+B" → "B"` 把这条容忍钉死了）。于是模型最自然的写法
  ——「给我的每行内容加个 `+`」——会被静默接受，且每个缩进行都少一格。
- 工具回报只有一句 `Edit applied successfully.`，diff 虽已算出来但只进
  `metadata`（`edit.ts:708`），不在 output 文本里。**没有任何地方响。**

**解析器侧无法修**：`+  const`（错误形态）与 `+ ` + ` const`（合法的 1 空格内容）
逐字节相同，意图不可判定。且收紧成必须带空格会破坏 `"+B" → "B"` 这条既有契约。

## 决策

- `edit.md`（即工具描述本身，`edit.ts:11` 直接 import）补一段缩进示例：
  `replace 3..4:` + `+   const x = 1`，并明说"这样写出来是 2 空格缩进"。
  Rules 第一条扩成完整语义：分隔符不是内容、N 空格内容要 N+1 空格、
  **数错会让每一行左移一格且仍然报成功**。
- `test/tool/edit.test.ts` 补三条回归：正确形态（3 空格 → 2 空格内容）、
  错误形态可复现（2 空格 → 1 空格内容，证明不是解析器抖动）、多层缩进 insert
  逐字保留。错误形态那条是故意钉住的——它把这个坑的形状固定成测试，
  以后谁改 `/^\+ ?/` 会先撞红。

## 模型可见改动的四问

1. **模型看到什么变了**：edit 工具描述的 hashline 格式块后多一段缩进示例
   （约 8 行），Rules 第一条从一句话扩成三句。参数 schema 未动。
2. **token 影响**：`edit.md` 2726 → 3219 字节，**+493 字节 ≈ +123 token**，
   落在每次请求都要付的工具描述固定前缀上。
3. **KV cache 影响**：工具描述位于 system prompt 的工具 schema 区，改动它 =
   从工具 schema 起往后的前缀**作废一次**（含全部历史消息），之后恢复稳定。
   这是一次性成本。
4. **注入项有没有硬上限**：`edit.md` 本身没有字节上限——它想涨就能涨，而每一字节
   都按固定前缀计价。本次 +123 token 单独点名。后续若继续往工具描述里加说明，
   应先问"这段值不值每轮都付"。

## 备选与否决理由

- **解析器收紧为必须 `+ `（拒绝 `+foo`）**：否决——`edit.test.ts:643` 钉住了
  `"+B" → "B"`，且空的 `+` 就是空行是合法用法。改了会破坏现有契约，
  而它本来也拦不住我犯的错（`+  const` 是合法的 `+ ` + 1 空格内容）。
- **在 output 里回带 diff**：暂缓——diff 已经算过并进了 `metadata`，TUI 会渲染；
  再复制进 output 是每次 edit 都翻倍的 token 成本，而为的是一个已被文档+测试
  覆盖的坑。若后续再犯，再上这条。
- **靠 formatter 兜底**：不可靠——`format.file()` 只对配置了 formatter 的语言生效，
  markdown / json / 纯文本没有。本会话三个错有两个在 .ts 上，是靠 oxlint 而非
  formatter 发现的。

## 后果

- 文档给出了可照抄的缩进样例，规则的三个要点（分隔符非内容、N+1、数错仍报成功）
  都写进去了。
- 回归钉住了正确与错误两种形态，`/^\+ ?/` 的语义从此有直接覆盖。
- 残留风险：模型仍可能不看示例照老写法写。机制上的下一道闸是 output 回带 diff
  或 hashline 应用后比对缩进轮廓，都留待复发再上（记忆规则：3 次以上必须机器门禁，
  这是第 1 次归档）。
