# 手动召回按完整记忆装箱

状态: implemented

## 问题

`seed/scripts/recall-memory.mjs` 先拼接全部候选再按字符截断。一个靠前的大条目会被截成半段，同时挤掉后面本可放下的完整短条目；模型既看到不完整经验，也失去更可执行的候选。

`packages/opencode/test/seed/recall-memory.test.ts` 用隔离 SQLite 库复现：预算为 100 token 时，大条目 `#30` 超限，短条目 `#20` 可容纳；旧实现输出被截断的大条目而不含 `#20`。

## 决策

手动 `/recall` 改为采用与 `src/util/token.ts` 相同的每四字符 token 估算，按照排序依次装入完整条目。单条超预算时只跳过该条，继续尝试后续候选；不再对最终结果做任意字符切片。

## 备选与否决理由

- **保留最终字符截断**：否决——会产生不完整的模型可见经验，且无法利用剩余预算。
- **超预算时立即停止**：否决——靠前的大条目不应阻止后续短条目被召回。

## 后果

`RECALL_MAX_TOKENS` 成为手动召回的显式上下文预算，默认 1125。输出条目数可能小于检索命中数，这是完整性优先的正常结果。
