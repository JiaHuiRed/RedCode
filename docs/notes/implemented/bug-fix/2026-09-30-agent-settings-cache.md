# 智能体设置跟随后端实例失效刷新

状态:implemented

## 问题

设置保存全局配置后立即重新读取智能体，而全局配置接口在返回响应后异步释放实例。智能体定义缓存绑定实例，提前读取可能拿到旧模型。随后 `global.disposed` 只触发 bootstrap 刷新；bootstrap 的初始化保护和刷新冷却可能抑制该请求，全局智能体查询也没有独立失效路径。表现为文件已保存 GPT-6 Luna，下拉仍显示旧模型，重复点击不能可靠更新。

## 决策

- 保存过程中显示正在选择的模型和档位，禁用该卡片的两个选择器，避免并发保存互相覆盖；失败显示错误并回滚显示。
- 保存响应确认后只更新查询中对应智能体的模型/档位，不立即读取尚未释放的实例。
- `global.disposed` 和 `server.connected` 单独失效所有目录的智能体查询，独立于 bootstrap 冷却；不失效 MCP 查询。
- explore 和 execute 的全局配置与 seed 模板设为 `openai/gpt-6-luna`、`xhigh`，不改变工种权限与提示词。

## 备选与否决理由

- **服务端等待全部实例释放后再返回保存响应**:否决——全局实例清理范围大，设置交互不应等待 MCP/插件收尾。
- **取消 bootstrap 冷却**:否决——扩大刷新影响面，重新引入 MCP 重复启动风险。
- **固定延时后刷新**:否决——无法保证慢实例已经释放。

## 后果

保存成功的 UI 先展示已确认配置，后端失效事件随后带回完整定义。断流后重连同样刷新智能体查询。模型可见提示词、工具目录和固定前缀不变；下一次子代理请求按新配置选择模型和推理档。

验证使用真实 QueryClient 和实际事件 reducer：两条新增用例修改前失败，修改后全文件 21 条通过，MCP 查询保持有效。app 类型检查和格式检查通过；live/seed JSONC 校验通过，源码 doctor 为 6 ok/3 warn/0 error。运行 API 确认两个工种配置，实际新派 explore 消息记录为 `openai/gpt-6-luna`、`xhigh`。未通过当前桌面进程点击验证源码修复，当前进程尚未加载修改后的 UI。
