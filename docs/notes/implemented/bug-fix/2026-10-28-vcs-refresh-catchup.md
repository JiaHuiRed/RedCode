# Git 变更刷新在飞合并与补刷

状态：implemented

## 问题

文件树或审查面板打开时，VCS diff 可能持续数秒。原来的在飞守卫避免了变更事件反复取消耗时请求，但防抖到期时直接丢弃通知：如果这是最后一次通知，旧结果会留在界面。

隔离浏览器复现中，第一个 diff 响应在飞时发送文件变更，防抖到期后放回旧结果，界面仍显示旧文件且没有第二次请求；请求结束后再发送事件才显示新文件。

## 决策

按查询 key 防抖并合并通知。防抖到期时若相关查询仍在飞，保留待刷新状态；查询结束后失效对应 key 并补刷。新通知重置该 key 的防抖，页面销毁时清理定时器和订阅。刷新不取消在飞请求。

## 备选与否决理由

- **在飞直接丢弃**：否决——最后一次通知可能没有后续事件补救。
- **每次通知取消并重新请求**：否决——慢 diff 遇文件变更风暴会反复重算。
- **请求一结束立即响应任何在飞通知**：否决——快速请求配合密集通知会绕过原有防抖。

## 验证与边界

QueryClient 定向测试覆盖在飞补刷、请求在防抖期内结束、多次通知合并、key 切换和页面销毁。隔离浏览器同一场景验证请求结束后自动显示新文件，后续独立事件仍能刷新；使用的是受控 mock 数据，不能替代实际 Git 工作区验收。
