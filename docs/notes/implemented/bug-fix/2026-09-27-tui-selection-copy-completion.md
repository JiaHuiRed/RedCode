# TUI 剪贴板完成后再清除选区

状态:implemented

## 问题

TUI 的剪贴板写入需要异步调用系统命令。原先鼠标选区复制在启动写入后立即清除选区，写入失败时用户失去重试目标；控制台复制则是在异步写入结束后无条件清除，期间新选中的内容也可能被旧回调清掉。

## 决策

复制入口共用异步收尾逻辑：成功后仅当当前选区仍与复制开始时的文本、锚点、焦点及 renderable 身份一致才清除；写入失败保留选区。控制台复制也走同一逻辑。

## 备选与否决理由

- **写入开始就清除**：否决——失败会丢失用户选区。
- **只比较选中文本**：否决——不同位置或 renderable 上的同文选区无法区分。

## 后果

若写入期间终端重排导致选区身份变化，旧选区会保留而不会误清用户的新选择；用户仍可自行用 Escape 清除。
