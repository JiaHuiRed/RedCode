# TUI 新会话导航完成后再清除已发送草稿

状态:implemented

## 问题

新会话发送成功后，composer 先立即清空，路由却延迟 50 ms 才跳到新会话。用户会看到空白输入框；若只延迟清空但让提交锁提前释放，交接窗口又可能触发重复提交。Prompt 卸载时还会把非空输入暂存给新 Prompt；因此导航后再清理只会清掉旧组件，新 Prompt 已恢复出刚发送的消息。

## 决策

新会话路径等待原有 50 ms 导航交接。计时到期后先通过提交 revision 判断输入期间是否变化：仍是已发送版本就先清空，再导航，避免 Prompt 卸载时暂存已发送内容；若用户编辑过，则保留当前草稿，让 Prompt 生命周期交接逻辑带到新会话。清空和导航发生在同一回调中，不产生可见空白帧。等待期间提交锁继续占用，避免重复发送。shell 模式复位也放在成功消费路径中。

## 备选与否决理由

- **发送成功后立即清空**：否决——与延迟路由形成可见空白窗口。
- **导航后再判断并清理**：否决——源 Prompt 卸载会先把已发送内容暂存，新 Prompt 随后恢复它，清理旧组件无法清除新草稿。
- **按文本相等而不是 revision 判断**：否决——文本被编辑后又恢复原值时无法识别期间发生过的新输入。

## 后果

若用户在交接期间编辑，当前 draft 会原样交给新会话，不会被旧提交清掉；若未编辑，已发送内容不会被草稿恢复机制重新显示。
