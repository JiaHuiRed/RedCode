# TUI 新会话导航完成后再清除已发送草稿

状态:implemented

## 问题

新会话发送成功后，composer 先立即清空，路由却延迟 50 ms 才跳到新会话。用户会看到空白输入框；若只延迟清空但让提交锁提前释放，交接窗口又可能触发重复提交。

## 决策

新会话路径保留当前 composer 内容，并等待原有 50 ms 导航交接完成。先导航，再通过提交 revision 判断输入期间是否变化；只有仍是已发送版本时才清空。等待期间提交锁继续占用，避免重复发送。shell 模式复位也放在成功消费路径中。

## 备选与否决理由

- **发送成功后立即清空**：否决——与延迟路由形成可见空白窗口。
- **保留即发内容但不等待 handoff**：否决——提交锁会提前释放，交接期间可重复发送。
- **按文本相等而不是 revision 判断**：否决——文本被编辑后又恢复原值时无法识别期间发生过的新输入。

## 后果

若用户在交接期间编辑，当前 draft 会原样保留，不会被旧提交清掉；其中可能仍包含已发送文本，用户可在新会话里继续编辑。
