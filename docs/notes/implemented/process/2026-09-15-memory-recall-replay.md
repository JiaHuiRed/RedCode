# 自动召回用人工标签回放校准

状态: implemented

## 问题

自动召回此前只有 TSV 次数、命中 ID 与耗时。它能说明系统“注入得很频繁”，却不能说明这些记忆对当前任务相关；因此无法安全调整阈值、预算或排序。

## 决策

自动插件保存包含实际渲染 reminder、候选命中词、排序票数、预算跳过原因的有界 JSONL 审计。`analyze-memory-recall-audit.mjs` 将审计与人工标签（消息 ID 对应期望 memory IDs）对比，输出：

- `Precision@injected`
- `Recall`
- 无记忆任务的误注入率
- 注入事件数和 token 的 p50/p95

未提供标签时脚本只报告客观用量，明确拒绝推断准确率。

## 备选与否决理由

- **以注入率代替准确率**：否决——高注入率可能正是噪声增加，不能作为切换排序规则的依据。
- **让模型自行给历史召回打分**：否决——会额外花费模型调用，并把评测目标和被评测系统耦合。

## 后果

标签需要从真实 coding 任务中抽取；任何新的召回排序在切流前必须先由此工具 shadow-run 并达到既定 precision/recall 目标。
