# 轮次远跳一次发布历史时间线

状态:implemented

## 问题

轮次目录可以定位到尚未载入的旧消息。`loadThrough` 会连续拉多页，而每页都会进入同步 store 并立即改变时间线的 user-message 投影，令虚拟列表反复重建行结构。该路径与普通用户逐页向上滚动不同：跳转期间用户看的是当前视口，目标到达前不需要逐页展示中间结果。

## 决策

`createSessionHistoryLoader.loadThrough` 暂存启动时的时间线投影；同步 store 仍逐页接收数据，轮次查找仍读取实时历史。目标到达、不可达或加载失败时，解除投影暂存，让当前完整消息列表一次性进入时间线。普通滚动加载保持逐页更新。

## 备选与否决理由

- **全局批量写入所有历史页**：否决——会改动同步层的通用分页语义，并影响普通滚动、重连和其他消费者；当前收益只针对轮次远跳期间的主时间线重排。
- **回滚未完成跳转的已载入数据**：否决——这些页面仍是有效缓存；跳转失败不应丢掉已经成功取得的历史。

## 后果

- 轮次远跳期间，同步层、导航与其他 store 消费者仍可见逐页数据；只有主时间线行投影延迟到操作结束。
- 页面异常或目标不在历史中时，已成功载入的部分历史仍会一次性显示，不做网络数据回滚。
- 该改动仅改善多页轮次远跳的中间重排，不是发送后滚动跳动或会话切换空白的根因修复。
