# 会话页增加用户消息侧边轨道

状态:implemented

## 问题

长会话中，用户消息之间有大量 assistant 输出，单靠滚动条向上翻很难快速回到某一轮。会话页已经有
`GET /session/:sessionID/outline`，它返回整份日志的用户轮次预览；消息时间线本身则只保留分页窗口。

## 决策

在桌面会话区左侧增加窄消息轨道，每个用户轮次显示一个可点击短线。轨道复用
`SessionTurnOutline` 使用的 outline 查询缓存，点击仍由 `session.tsx` 的 `jumpToTurn` 负责：
先通过 `loadThrough` 把目标用户消息翻进时间线，再调用现有的 `revealMessage` 定位。

轨道只渲染每轮一个轻量按钮，不复制消息正文；按钮的 `title` 和无障碍名称使用服务端已经截断的 prompt。
移动端不显示轨道，避免占用本来就窄的消息区。

## 备选与否决理由

- **从当前消息窗口直接生成轨道**：否决——历史窗口是分页后缀，长会话只能显示最近几轮，正好覆盖不了主要需求。
- **为轨道新增独立分页与滚动实现**：否决——会重复 `loadThrough`、虚拟列表和边界处理，容易与现有跳转链漂移。
- **把轮次目录固定成另一个侧面板标签**：否决——点击轨道需要常驻可见，不能要求用户先打开标签页。

## 后果

打开桌面会话时，outline 查询会成为轨道的常驻数据源；由于轨道与目录使用同一个 query key，
打开“轮次”标签不会再产生第二次相同请求。轨道本身可以滚动，当前被选中的轮次会沿用共享
`MessageNav` 的 active 状态。
