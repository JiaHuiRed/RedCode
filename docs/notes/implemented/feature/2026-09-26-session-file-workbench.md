# 同一会话工作区的并排与浮动

状态:implemented

## 问题

文件预览与 Review、Context 等导航已经共用胶囊，但阅读代码时宽桌面只能在聊天上方覆盖胶囊。扩大胶囊又会挡住聊天；频繁在聊天和代码之间切换缺少稳定的并排工作区。

## 决策

保留原有五项固定导航和动态文件标签，使用同一个 `SessionSidePanel` 与 `FileTabContent` 实例切换胶囊、并排和浮动。宽桌面并排时面板参与 flex 流，聊天区与面板共用宽度表达式，避免覆盖和双重让位；浮动时保留原 DOM，只切定位，并在拖动/调整大小结束后持久化几何。模式及浮动位置按会话保存，窗口较窄时回落到原有胶囊表现。

## 备选与否决理由

- **新建文件预览第四列、保留系统胶囊**：会让中等宽度下聊天被两列挤压，还要复制文件标签的焦点、选区和滚动同步。
- **引入通用 DockKit**：当前需求只有一个工作区的三种呈现形态，拆分树和多窗口拖放协议没有实际使用场景。

## 后果

- 并排最低保留聊天 480px 的布局预算；小窗口不启用并排，原有胶囊导航与文件内容不变。
- 全部模式切换只换 CSS 布局而不重建文件预览；同一会话切回来恢复其选择的模式。
- 浮动窗口仍在当前浏览器视口内，不是操作系统原生窗口；缩小视口时位置会钳制到可见范围。
- 并排工作台沿用侧栏毛玻璃：有壁纸时，外层磨砂卡片内的内容面必须透明，且浮起卡片的两侧外边距要从 rail 宽度扣除；无壁纸时内容面保留实色。左侧拖宽手柄在并排态也必须挂载，不能沿用「仅中桌面」条件。
