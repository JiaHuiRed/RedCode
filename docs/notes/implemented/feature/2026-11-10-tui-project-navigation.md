# TUI 同窗口项目导航：常驻连接与目录作用域分离

状态:implemented

## 问题

启动选择器只能在 Renderer 启动前选择目录；SDK、草稿与插件 API 绑定启动项目，不能通过修改标题或反复 `process.chdir()` 实现运行中的跨项目切换。实施依据为 `docs/2026-11-10-tui-multi-project-workspace-switch.md`，源码核对基线为 `5ec4e376`。

## 决策

- Renderer、Worker、退出流程及全局事件连接常驻；项目切换只重建目录 SDK、Project、Sync、Local、配置和视图。目录 SDK 的请求取消信号由常驻连接拥有，卸载视图只释放该视图的事件订阅，不取消原目录请求。
- 先验证已有目录并准备目标配置，再串行清理旧插件、提交新作用域。准备失败保留源视图和输入；切换代次排除迟到结果。插件使用已有 scope 执行清理与重新绑定，不能继续捕获旧 SDK。
- 导航身份为当前连接内的规范目录；草稿、光标、附件与阅读锚点按目录和会话分别保存。现有 Workspace ID 单独保留，不迁移会话、不复制修改、不注入“换目录”提醒。
- 前台事件优先按目录过滤，保留已知子 Workspace 的确认请求；后台事件入口仅维护已访问项目的运行/待确认摘要。返回时重新 bootstrap 和读取会话快照，权限恢复复用提问的快照与实时事件合并机制。
- 最近项目只持久化目录、名称、访问时间和上次会话，不保存消息正文。列表读取项目元数据，不批量启动历史项目的 MCP、LSP 或 watcher。
- 工作区管理沿用会话列表的形态：`ctrl+d` 两段式确认可把一条记录移出列表。删除只写「隐藏名单」（`projects.json` 的 `ignored`），不动目录、不动服务端项目行与会话；当前工作区不可删；重新切回该目录会重新记录并自动撤销隐藏，避免删了再也回不来。
- 显式路径与真实调用目录优先。仅编译产物的调用目录等于实际 EXE 所在目录时，才尝试恢复最近有效项目；没有可靠目录则进入未选择项目的首页，选择前禁止发送。不再调用 raw stdin 启动选择器。

## 备选与否决理由

- **整棵应用无清理地重挂**：会重复执行启动参数、注册全局资源，并留下捕获旧 SDK 的插件。
- **每个项目常驻一棵完整组件树或新建 Worker**：增加后台视图与连接开销，且不是第一版必要条件。
- **调用现有 Workspace warp**：那是会话迁移能力，不是独立项目导航。
- **切换时 reload/disposeAll**：会销毁仍在执行任务的原项目实例。

## 验证

- 生产 Worker / RPC / SDK 的双目录集成：两个目录分别读取自己的路径和配置；A 等待权限期间 B 完成写文件；用原目录及 Workspace 回复后 A 继续完成，文件没有跨目录写入。测试为 `test/cli/tui/project-worker.test.ts`，1 pass、10 assertions。
- 目录事件隔离及提问恢复：10 pass；项目 SDK 卸载/迟到订阅清理与连接取消所有权：2 pass；草稿数据操作：6 pass。
- 启动、最近记录、会话目录匹配：16 pass；TUI 配置：37 pass；插件清理、重新绑定与安装入口的定向用例通过。
- `packages/opencode` typecheck 通过。真实 Windows PTY 使用 Node 驱动当前源码，隔离 HOME / DB / 配置后脚本化跑完整往返（`workspace-a` → 中文含空格 `工作区 B` → 回 `workspace-a`）：A 输入 `draft-A`，切到 B 时标题变为 `工作区 B` 且输入框为空（A 的草稿没有串过去），B 输入 `draft-B` 后切回 A，A 的输入框恢复为 `draft-A`。无效路径 `E:\missing-workspace-test` 在添加面板内报 ENOENT 并保留输入，源工作区与草稿不受影响。
- 真机操作暴露并修掉两个缺陷（纯函数测试抓不到）：① 选择器搜索后按回车，选中项仍停在首行「添加工作区…」，会打开添加面板而不是切到目标工作区——「添加工作区」现在只在搜索命中时出现，且 `DialogSelect` 在列表缩短后把越界索引归零（否则回车被 `!option` 守卫静默吞掉）；② 切回第二个项目时插件运行时重新 `init()` 再次创建 slot registry，抛 `createSlotRegistry called with a different context` 直接崩掉整个 TUI——registry 改为按 renderer 复用。
- 未覆盖：会话内阅读锚点在 PTY 中未实测（脚本往返只走了首页）；切换瞬间仍在途的附件粘贴由 `draft.ts` 单元测试覆盖，未做真机时序复现。

## 后果与边界

仅本地 TUI 启用项目导航；attach 保持现有连接方式，不把远端路径当本地目录校验。项目重型视图不保活，返回需重新同步；目录配置 runtime 和轻量视图快照在 TUI 生命周期内保留。退出应用仍沿用原任务退出行为，不承诺关闭 EXE 后任务继续。

本次没有新增模型可见注入、工具 schema 或提示词。固定前缀、注入 token 上限和 KV cache 布局不变；目标项目在新会话中使用其原有配置与指令加载链。
