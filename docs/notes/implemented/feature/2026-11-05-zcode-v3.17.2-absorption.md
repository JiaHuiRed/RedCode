## 决策一：命令模板的 `` !`cmd` `` 停止解析期执行

- 原状（= ZCode 刚抛弃的旧设计）：`SessionPrompt.command` 在解析期用 `Process.text`
  直接执行模板里的 shell 块、输出拼进 prompt——绕过权限层与审批、UI 不可见、执行失败
  影响发送路径；且 `$ARGUMENTS` 先替换，用户参数里夹带的 `` !`evil` `` 也会被解析期执行
  （RedCode 比 ZCode 旧版多出的一个注入面）。
- 改法：`ConfigMarkdown.handoffShellBlocks`（`config/markdown.ts`）纯文本改写——每个块
  替换为「来源声明 + fenced bash 代码块」，声明写明这一步来自命令文件而非 RedCode 本体
  （prompt-injection 防线：让模型按外部内容对待）。执行走 Bash 工具 → 权限层决定
  放行/询问/拒绝，用户在 UI 看到工具调用。改写永不失败，send/queue/edit/retry 与普通
  prompt 完全一致。
- **顺序是安全不变量：改写先于 `$N`/`$ARGUMENTS` 替换。** 参数文本永远不被当成 shell 块。
  块内的 `$ARGUMENTS` 在改写后的 fenced 文本上替换（recall.md 这类命令 seed 零改动）。
- `SHELL_REGEX` 同步收紧为 lookbehind 形态（`!` 前必须是行首或空白），正文 `Warning!`
  后跟代码段不再误判。被删函数：`ConfigMarkdown.shell`、prompt.ts 本地 `bashRegex`
  及整段 `Process.text` 执行。
- Bash 工具（`tool/shell.ts` 的 `shellEnv`）随每次调用注入 `REDCODE_SESSION_ID` 与
  `REDCODE_PROJECT_ROOT`（会话创建目录，不随 cd 漂移）：命令脚本原来靠解析期注入的
  env 定位项目，转交后这组变量由 Bash 工具供——env 契约随执行路径迁移必须跟着走
  （ZCode 的教训：它的 `!` 块转交后原解析期变量断了，插件脚本跨会话生效）。
- 行为代价（有意接受）：依赖解析期输出的命令从「输出直接进 prompt」变为「模型先调一次
  Bash 工具再消费输出」，多一次工具往返；换来执行可见、可审批、可取消。Windows 上
  shell 选择不再参与模板展开（原实现区分 bash/PowerShell 执行，现在统一交 Bash 工具的
  既有 shell 解析）。

## 决策二：MCP stdio 启动失败带证据链

- 原状：stderr 逐 chunk 只进 `log.info`，`status.error` 只有 SDK 的 "Connection closed"
  ——「误配置要响」的隐蔽变体：响了个寂寞。
- 改法（`mcp/evidence.ts`）：`transport.stderr` 逐 chunk 进有界尾部缓冲（4000 字符）；
  连接失败时 `describeLocalFailure` 按 error message 分诊（命令不存在/超时/进程早退/
  其他）配一句英文建议，附脱敏截断后的 stderr 证据（`strip-ansi` → KEY 含
  TOKEN/SECRET/PASSWORD/CREDENTIAL/API_KEY 等的 `KEY=VALUE` 整值遮蔽 → 截尾 512 字符）
  拼进 `status.error`。脱敏在截断之前做：截断丢前缀不会漏遮。分类只看连接错误本身，
  不按 stderr 内容改判。
- 测出来的平台事实：Windows 上「命令不存在」不产生 ENOENT——spawn 错误被 transport
  吞掉，同样报 Connection closed。因此 Connection closed 分支在证据为空时换措辞
  （「命令可能根本没启动」），不承诺一句不存在的「stderr below」。
- 边界：只做 stdio 连接期。remote HTTP/SSE 无 stderr；健康检查期失败（`mcp/health.ts`
  路径）不挂证据，留待办；不加 failureKind 字段——error 保持 string，零 schema 变更。

## 模型可见改动（四问）

- shell 块转交：系统提示词、工具 schema、注入段零改动——固定前缀与 KV cache 无影响；
  变化只在含 shell 块命令的 user message 内容（块 → 声明 + fenced 代码块）。新增注入项
  `handoffShellBlocks` 声明为固定 ~40 词常量，按构造有界；块内容是命令文件既有内容。
- Bash env 注入：`REDCODE_SESSION_ID`/`REDCODE_PROJECT_ROOT` 进进程环境，不进模型上下文。
- MCP 证据链：`status.error` 是 UI 展示面，不进模型上下文；有硬上限（建议固定文案 +
  证据 ≤512 字符）。
