# 让短聊天在下一次见面时接得上

状态为 implemented。

## 问题

新伙伴第一天没有旧档案。即使双方聊得很开心，只要那一轮没调日记工具，新建会话的启动资料里便找不到刚聊过的小事。反过来，已导入几个月日记的伙伴也很难在普通闲聊时自然想起一篇旧日记。历史工具已具备搜索和回读能力，缺的是在合适的时候把少量证据送到当前回复。

## 决策

- 同一伙伴和目录的新主会话，在首条用户消息上，从上一个有效主会话最近八条消息中取最多四条有角色和当地日期的可见发言。排除已归档或已回退的会话、摘要、工具正文、待投递消息和已成功写过记忆的轮次。每条最多 380 字节。原会话间隔六小时后继续聊天，可在本次回复时补记一件仍值得留下的事。日记使用写入日，回顾时在正文区分事情原来的日期。
- 复用现有个人档案检索和读权限。短消息以整句或词语重叠在最近优先的一页日记里找线索，取一条最多 640 字节的摘录。包括中文相邻双字。它适合找回共同用过的词，遇到别称、隐喻或很大的旧档案时，模型仍可用现有记忆工具继续找。按消息进行一次可选查找，400 毫秒预算耗尽时继续正常回复，最多扫描现有工具的一页（8 MiB）。
- 新的 retain 动作校验本轮真实用户消息的原文，连同来源和当地日期存入伙伴自己的 MEMORY.md。按消息与引文去重，原文件保留。当天见闻仍用 remember，由伙伴用自己的口吻挑值得记的片段。两个动作沿用既有锁、幂等记录与编辑权限。GUI 用同一档案的文件接口按日期读日记。
- 定时反思需要单独的调度、授权及推理成本。本次利用正在发生的聊天来记事。之前的决定见 [伙伴范围的历史召回](2026-11-17-companion-session-recall.md)。

## 模型可见四问

1. 固定 Chat 基础提示末尾从个人记忆归属接到 “Let familiarity grow from ordinary conversation.”。原有 search/read/remember 工具新增 retain，说明区分共同经历和有原文依据的长期偏好。动态尾部以 “Earlier personal context, quoted as historical evidence.” 标明材料性质。
2. Chat 基础提示 1845 → 2292 字节（+447，约 112 个估算 token）。工具说明 2292 → 2656 字节（+364，约 91 个），另加 retain 枚举，JSON 枚举约 2 个估算 token。估算沿用仓库英文四字符/token 口径。无证据时无召回正文。
3. 发布后的第一次请求会从 Chat 基础提示末尾或工具声明变化处重建相应前缀缓存。逐轮摘录只送到请求尾部；写日记、保留引文沿用新会话或冷启动重读个人档案的行为。Code 和子任务没有这段召回。
4. 尾部共限 3072 UTF-8 字节。retain 的用户原话最多 1024 字节，只回传写入状态。启动个人上下文保留既有 32 KiB 总帽，现有 search/read 的返回量仍按登记表上限执行。GUI 日记内容不会注入模型。

## 验证

合成 provider 用一位空白伙伴和两次独立会话验证未写入日记的蛋挞趣事、长期偏好的真实来源、旧档案的正文与文件头、拒绝虚构引文，以及某篇较早日记只在相关请求的尾部出现。浏览器用合成日记验证打开最新一篇并切换到较早日期。人格表达和什么时机值得写日记仍由实际模型决定。
