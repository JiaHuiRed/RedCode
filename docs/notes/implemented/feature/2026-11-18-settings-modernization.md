# RedSpace 设置：伙伴、Code Soul 与可操作的配置入口

状态：implemented

## 问题与产品边界

设置页把大多数选项挤在「通用」里；Soul 阵容与正文预览有多层滚动，Chat 与 Code 共用默认身份入口，底部还显示 RedCode Desktop。文件路径只能查看，开关的选中悬停态失去颜色，部分导出、断开与语音失败没有可靠反馈。新用户必须先导入伙伴才能说第一句话，已有伙伴的日常入口又持续强调资料来源。

本次以用户先行认可的独立 HTML 预览为设计依据。用户截图中的第一、第四张是现有 RedSpace，第二、第三张是其他产品参考；未把参考产品未接通的能力当作现有功能。

Chat 是 RedSpace 的日常聊天能力。已有伙伴直接继续相处；首次使用可以先发消息，也可以通过正常对话慢慢认识彼此。身份、资料、记忆的日常界面不显示迁移标签或导入文件数量。需要添加已有资料时，在「文件与数据」里提供明确的维护入口。

用户追加要求保留「新建伙伴」，总共最多两位，以便在保留现有伙伴的同时亲自测试完整的新用户体验。相识流程的可点击设计见 [Chat 初次相识预览](../../../previews/chat-first-meeting.html)；预览使用显式标注的示例回复，不读取真实档案，也不代替模型行为验证。

## 界面与设置作用范围

- 设置分为十四个入口：聊天伙伴、Code Soul、通用、外观与显示、声音与通知、快捷键、供应商、模型、智能体、权限、MCP、设备连接、文件与数据、诊断记录。保留原来的主题、字体、壁纸、通知、音效、TTS、桌宠与更新能力。
- 设置容器统一导航、搜索、标题和卡片间距；主内容只有一个滚动面板。窄窗口使用统一的命名容器断点，避免侧栏与移动下拉同时出现。编辑弹窗有独立可滚动正文，保存按钮可达。
- 开关改为有主题色的圆角轨道，保持选中悬停颜色，提供键盘焦点；滑块、滚动条和下拉控件同步调整。`SettingsRow` 通过 `FormField` 将可见标题与说明关联到真正的 Switch、Select、TextField 控件。
- 首次打开默认进入聊天伙伴；以后恢复上次分区。显式深链和持久化读取完成前的用户点击优先于晚到的存储值。首次拖动设置窗口以实际边界为起点，避免从视口大小跳变。
- 本机显示昵称、头像和模型可见性是本机偏好；伙伴的「关于你」写入真实 USER.md；Code 默认 Soul 仍使用既有本机偏好；服务器默认模型、智能体与工具行为写入真实服务器配置。自动批准明确作用于当前会话，或未打开会话时的当前项目。
- 模型页区分服务器默认模型与选择器可见性；智能体页提供默认 Code agent、交互终端 Shell、Windows Agent Shell、任务校验、文件快照、自动上下文整理、旧工具输出精简与 token 上限。
- 移除没有消费者的旧 `followup` 设置接口与强制回写逻辑；既有持久文件中的旧字段不被作为新选项重新展示。已有会话进度条偏好补上设置入口。
- 产品显示文案统一为 RedSpace，实际 `.redcode` 存储路径、provider 标识与协议字段保持兼容。

## Chat 与 Code 的身份分离

`POST /companion/initialize` 只在没有伙伴时创建中性的聊天伙伴，并幂等复用已有伙伴。显式的 `POST /companion` 则用于新建第一位或第二位，接受可重试的 `requestID`。两者与导入真实新增分支共用服务端伙伴目录的登记锁，锁内重新检查两位上限。满额后，同一创建请求的重试、已有身份的幂等导入及追加历史仍可继续；历史数据若已有超过两位，完整保留访问，只停止新增。

新用户第一条消息按真实链路执行：initialize → 创建绑定 Chat 会话 → `promptAsync` → 导航到该会话。显式新建后直接进入新伙伴的空白 Chat，使用独立 Soul、工作目录与记忆，不复制另一位伙伴的个人资料。当前聊天对象按服务与稳定 ID 保存；显式 URL 指向不存在的伙伴时显示错误，不悄悄切换对象发送。设置中的编辑对象与正在进行的聊天分开，只有「去聊天」或显式切换才导航。

首页的首句草稿、准备好的会话、消息 ID、失败状态按服务和伙伴分别管理；持久化仅保留重试所需的会话标识与文本，恢复时清除运行锁。草稿同样使用服务范围内共享状态，旧页面晚到的清理或转交按当前值合并，避免覆盖重新进入页面后编辑的另一份草稿。初次创建前的未绑定草稿只转交给本次建立的伙伴；异步请求完成时核对当前对象，不能清除另一位的草稿或把用户拉回已经离开的聊天。

首次发送不能把 `promptAsync` 的 HTTP 204 当作消息落地：它仅启动后台任务。前端等待对应 session / message ID 的非空用户文本 part，通过 SSE 或 GET 查证；只有空消息头不算接受。统一 8 秒 deadline 覆盖发送与查证请求，并将 AbortSignal 传给 SDK。确认后才消费草稿并导航；未配置模型或传输失败时保留输入与重试标识，旁边提供模型 / 提供商设置入口。模型预检仅使用服务器返回的已配置提供商清单，模型优先级仍由服务端决定。

### 可选的初次相识

首次进入的说明是「想先认识一下，或直接聊，都可以」。点击「先认识一下」发送真实可见的用户消息「我们先认识一下吧。」，随后由正常 Chat 回复；界面不伪造助手问候，也不从聊天文字中用正则提取姓名。开始相识会保留用户原有任务草稿。TUI 使用已有草稿暂存机制，原草稿可以从暂存列表恢复。

若先发送任务，先正常处理任务；仅在真实回复完成且会话空闲时展示一次可选邀请。已有伙伴默认不展示首次欢迎或相识提示。四种状态记录的是用户对流程的选择，名字不作为完成条件：

| 状态        | 含义                                                             |
| ----------- | ---------------------------------------------------------------- |
| `available` | 新伙伴，可以开始相识，也可以直接聊天或做任务。                   |
| `active`    | 用户选择了相识；仅在与当前消息相关时自然继续，每次至多一个问题。 |
| `paused`    | 先聊别的，停止自动提示；之后可以从设置继续。                     |
| `complete`  | 收起相识入口，日常资料编辑和聊天照常可用。                       |

旧档案没有状态时视为 `complete`，兼容此前 `needsSetup: true` 的未完成新档案为 `available`。普通改名或编辑 USER 不隐式结束流程；两个称呼都留空也可以暂停或结束。用户一次说出两方称呼时不重问；只说一方或转去做任务时，不追问必填项。

`companion_profile` 是只属于绑定主 Chat 的窄资料工具。它从当前真实用户消息核验 `sourceQuote`，保存明确选定或认可的伙伴称呼 / 用户称呼，或暂停、结束相识。它不接受任意伙伴 ID、路径、Soul 正文或整份 USER；Code 与子任务不可调用。引文匹配只证明来源，不能机械证明一句话在语义上授权改名，工具说明仍要求有歧义时自然询问，禁止把示例或建议直接写成事实。工具成功后才能声称已经保存。

称呼写入 `IDENTITY.md` 与 `USER.md` 开头的专用受管段，其他原文逐字保留。伙伴显示名同步到界面，当前称呼在有界个人上下文中优先于旧的显示标签；不改写 Soul 的人格、关系和冻结正文。日常记忆继续使用 `companion_memory` 保存真实、值得留存的内容，不为新伙伴预写共同经历，也不承诺每条聊天都会自动成为长期记忆。

Chat 资料页管理对应伙伴的显示名、本机头像、Soul、关于用户的资料与记忆文件。资料编辑保留已有 USER 原文，只把自己写入的称呼字段作为独立段落处理。草稿按服务器和身份隔离，保存前核对源版本，失败保留输入；头像与资料一起确认保存。

Code 阵容、Code 新会话选择器与最终提交使用相同的过滤与默认解析：排除已绑定 Chat 伙伴的 Soul，依次选有效本机默认、服务器默认、可用 Code Soul；没有候选时沿用内建无 Soul 行为，不要求用户先填写身份。服务端也对未显式指定 Soul 的新 Code 会话做同样的排除。现有会话及显式指定的身份不被重写。

`PUT /soul/:id` 写入 `Soul.details.path` 的实际注册表文件，支持与 ID 不同名的现有文件；不误写工作区里保留的 SOUL.md 副本。ID 不可改变，沿用原有解析与大小校验，原子保存保留文件权限。既有会话通过 `soulBodyHash` 继续读取原冻结版本。

显式保存 USER、受管称呼或相识状态会推进 `profile.json` 内部的 `contextRevision`。每个 Chat 会话及每个模型缓存分别比较版本，在下一次组装时只刷新个人上下文段。环境、工程指令、MCP、工具、历史消息和 Soul 冻结版本保持；不通过全量清缓存或仅 HTTP handler 的旁路生效。资料页面或聊天工具保存的称呼可用于当前聊天的后续回合。

## 文件操作与真实反馈

文件页使用 `/path`、伙伴详情、instructions、skills、LSP、formatter 的真实返回结果。可打开或定位配置目录、工作目录、Soul、USER、MEMORY 及技能源文件；浏览器与远程连接仍能复制路径。原生打开和资源管理器定位限于桌面 sidecar，WSL 路径沿用平台映射；手工 HTTP / SSH 连接不被误当成本机文件。

桌面增加 `revealPath`、日志目录查询与打开入口。Electron `shell.openPath` 返回非空错误字符串会转为失败；打开本机桌面日志不经过 WSL 服务路径转换。当前服务器日志只在真实本机服务上下文提供。

诊断导出只在真实文件导出完成后报告成功；部分成功保留已保存路径及失败原因。供应商断开不再吞掉失败或提前隐藏仍连接的项。手机共享只允许实际桌面 base sidecar，远程页面仍可停止已经运行的本机共享。

MCP 分开显示当前连接状态与随服务启动设置。未加载、请求失败和未知状态不被显示成确定的断开。完整定义中的 `tools` / `cwd` / `timeout` 可恢复默认；环境变量与请求头支持修改和清空；JSON / JSONC 落盘语义一致；仅修改 `enabled` 保留其他配置。服务器默认模型恢复「自动」实际删除 `model` 键。

TTS 沿用既有 MiMo 接口、八个音色和 5,000 字符上限，抽出共享请求函数，增加 30 秒超时、取消、可见错误及音频资源回收。设置页可直接试听；错误信息不回显密钥或原始服务响应体。

## 模型可见四问

### 1. 模型看到什么改变

新建的中性伙伴使用以下默认 Soul 正文，末尾有一个换行：

```text
Respond helpfully to the user's messages. Do not assume personal details or a relationship that the user has not shared.
```

不预设情感关系或私人经历。已有伙伴的初始化调用直接复用档案，未编辑时 Soul、USER、MEMORY 不被重写。显式 Soul / USER 编辑使用用户提交的原文；Code 默认纠正只改变未显式选择身份的新 Code 会话。

Chat 固定契约新增「当前称呼优先于旧显示标签、只保存用户明确选择、不主动展开相识问答」一段；原先的 `a bounded snapshot from the start of this conversation` 改为 `It normally stays stable during a conversation; explicitly saved profile changes refresh this personal context in later turns.`，使描述与实际刷新契约一致。仅 `active` 的伙伴在 bootstrap 加入固定 `### Getting acquainted` 指导，原文位于 `companion.ts` 的 `INTRODUCTION_PROMPT`。

所有绑定主 Chat 增加 `companion_profile` 的 schema 和工具说明，用于确认称呼与结束 / 暂停相识；既有伙伴也有这项普通资料能力。因此不能声称已有 Chat 的固定提示词和工具 schema 是零字节变化；可以保证既有档案不会被初始化覆盖，也不会自动开启相识。

### 2. Token 影响

以仓库 `Token.estimateReporting` 实测：默认正文落盘 121 UTF-8 bytes；Registry 去掉末尾换行后 120 bytes，约 30 诊断 tokens。沿用现有身份包装后 186 bytes，约 47 tokens；空 USER / MEMORY 的引导格式为 28 bytes，约 7 tokens；两段加分隔合计 216 bytes，约 54 tokens。这是诊断估算，不等于供应商计费。

上述 216 bytes 是中性 Soul 与空个人上下文本身的基数，不包含本次新增的 Chat 固定契约和资料工具。相对于本次基线 `6f9229cf7c8a58fa312d430f45fc5768172c3d60`，固定增量的实测为：

| 项目                                      | UTF-8 bytes | 诊断 tokens |
| ----------------------------------------- | ----------: | ----------: |
| Chat 契约，修改前                         |       1,262 |         316 |
| Chat 契约，修改后                         |       1,845 |         461 |
| Chat 契约增量                             |        +583 |        +145 |
| 仅 active 的相识指导                      |         821 |         205 |
| 资料工具 description                      |       1,348 |         337 |
| 资料工具 canonical 定义（含 description） |       1,726 |         432 |

`session/prefix-shape` 给资料工具单条定义的 cost 为 440 tokens，包含数组壳的 capture 为 441；这些口径不能与 canonical JSON 的 432 相加。Provider 的 schema 变换可能带来额外包装开销。工具描述总预算实测为 29,916 / 32,768 bytes。Code 与子任务过滤该资料工具，不增加这项 schema。

用户编辑后的长度取决于实际正文；Code 回退的变化取决于原 Chat Soul 与实际选中的 Code Soul，不能给出一个统一固定差值。

### 3. KV cache 影响

原生伙伴第一条消息是新会话，没有旧前缀需要失效。Soul 编辑只影响之后新建会话，旧会话冻结版本不变；新会话最早差异位于环境 / 指令之后的 Soul 身份段。

本次 Chat 固定契约与工具清单发生版本性变化，升级后相应前缀有一次重建成本；最早变化来自 Chat base 契约和新增工具定义，具体的供应商序列化先后取决于路由。运行时仍维持稳定装配。USER、受管称呼或相识状态显式保存后，各会话 / 模型桶在后续调用只刷新 `CONVERSATION` 后的个人上下文段，这是资料生效需要的局部前缀变化；暂停或结束会移除 active 指导。`contextRevision` 不发给模型。未修改资料时前缀保持稳定；请求级回归对比连续回合、已预热模型的前后 system 与 tools。

### 4. 硬上限

- 原生固定 Soul：121 bytes。
- Soul 整文件：16 KiB；沿用渲染上限 16 KiB + 1,078 bytes，身份标签各不超过 256 bytes。
- USER 保存请求：16 KiB；USER / IDENTITY 实际注入各不超过 1 KiB。
- 长期记忆：24 KiB；最近两篇日记各 3 KiB；总 bootstrap 不超过 32 KiB。
- 通过资料接口或资料工具更新的伙伴称呼 / 用户称呼：各为单行、不超过 256 UTF-8 bytes；完整 USER 编辑继续使用整文件预算，不能据此假设已有自由文本中的任何称呼都短于 256 bytes。
- 资料工具的用户依据：`sourceQuote` 不超过 1 KiB，且需匹配触发当前回复的真实用户文本。
- 资料工具结果：小于 4 KiB，由两个各 256 bytes 的已验证输入与固定状态构成；仅回显本次更新的字段，不回显原文件中可能很长的受管行。已有 50 KiB 行的回归验证覆盖这一边界。
- active 相识指导：固定源码 821 bytes，并计入 32 KiB bootstrap 总帽，不增加第二份无界上下文。
- 已有 USER 原文的设置读取最多 4 MiB，供编辑器查看，不全量注入模型。

Soul、长期记忆和 bootstrap 可以超过 1K tokens；这些是既有明确上限，不扩大预算，也不添加无限制注入项。注入登记表新增固定原生 Soul 来源，并更新 bootstrap 的缓存稳定性说明。

## 验证与边界

- 核心初批定向：Companion 23、Config 103、Companion HTTP 4、Soul HTTP 7、Session Companion 5、Session Soul 9、真实 prompt 装配 2、Prompt cache 18，共 171 项通过。新增相识与两位伙伴后，Companion 服务 27 项、资料工具与 Companion HTTP 8 项、真实 prompt 回归 2 项通过；覆盖两实例新增竞争、满额重试、旧数据超过两位、来源引文、两位伙伴与双模型上下文隔离、原 Soul 快照不变。最新 Companion 实际 HTTP exercise 7 项、Soul 14 项通过；路由覆盖 193 项，无 missing / extra / skip。
- 前端定向覆盖真实提交失败重试、Code 默认最终请求、首聊提示资格、USER 原文往返、持久化晚到、真实控件可访问名称及状态、头像媒体兼容、三语词条一致性。桌面 / MCP / 诊断 / 供应商 / 语音的定向失败路径有独立测试。
- 新首聊异步控制器 9 项、发送落地确认 8 项通过：包括跨伙伴 / 跨页面迟到响应、恢复后复用原消息、相识失败保留任务草稿、204 但没有用户正文、空消息头、插件改写正文及永不返回的网络请求。真实 shared hook 的两次独立挂载、清缓存后重读持久化 2 项通过，确认旧页面回调不覆盖新页面草稿。
- TUI 真实弹窗 / 键盘 / Prompt 入口 17 项，以及隔离 CLI 子进程 create → 同请求重试 → init → list 链通过。覆盖已有文本与附件暂存、shell 输入模式切回普通聊天、相识 PATCH 迟到不串会话、旧伙伴不自动提示。
- App、UI、Desktop、Core 使用各自包脚本检查类型；App 生成真实生产构建；SDK 与 OpenAPI 由两条官方命令生成，并检查 drift。
- 安装时发现原有 `fix-keymap-junction.ts` 仍用已改名的 `packages/opencode` 作为 Solid 探测锚点。本批修为 `packages/redspace` 后执行仓库既有安装修复，解决重复 keymap 私有类型；没有升级依赖或改变 lockfile。
- 设置预览经用户先行审阅，新增相识流程预览覆盖八组真实 DOM 交互；本环境没有完成浏览器像素截图或 Windows Electron 实机验收。DOM、类型、HTTP 和生产构建证据不等于真实资源管理器、系统音频、实际供应商回复或打包安装验证。
- 文件页呈现后端已有路径及规则清单，不宣称已经提供完整配置优先级的来源追踪。未增加未经后端接通的记忆开关、后台自启动或模型记忆删除功能。
