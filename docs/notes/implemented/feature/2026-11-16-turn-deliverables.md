# 每轮回答末尾集中展示文件成果

状态:implemented

## 问题

Markdown 阅读、HTML 隔离预览、文件侧栏与返回工具已经存在，但用户需要从回答或工具日志里逐个找文件。路线图 A05 的「本轮成果归拢」尚未实施。本功能把已有文件查看能力连接到每轮的实际产出，不改变执行协议。

## 决策

- GUI 每轮最后一条助手内容后展示「本轮成果」卡片；该轮仍在运行时不展示，空集合不占位。文档、网页、图片、音频优先，其他文件随后。
- 只使用已加载助手消息中 `parentID` 属于本轮、状态为 completed 的 write / edit / apply_patch 记录。读过的文件、失败调用、其他轮次、Steering 人工留痕与工作区原有 Diff 不充当产出证据。不另请求模型，也不扫描工作区。
- 同一路径合并并保留最近操作来源；本轮创建后继续修改仍标创建。补丁删除移除卡片；移动用目标路径。Windows 按分隔符与大小写统一路径身份，文件名里的 `#`、`%` 等保留。工作区外路径不交给工作区预览器，避免打开同名错误文件。
- 默认四张，按需每次增加八张，可以收起。仅在可见的轮次末行挂载并归集；没有额外网络轮询或文件预加载。
- 点击卡片复用 FileOpenProvider 和既有预览槽，显式设置工具来源，因此键盘触发也有「返回工具」目标。「查看来源」复用搜索/引用的 jumpToTarget。Markdown/PDF 等走已有查看器；HTML 先打开文件，再由文件头的「浏览器打开」明确触发执行。
- 颜色使用既有主题变量，文件类型采用轻量色彩区分；自适应列宽、长文件名换行、可见键盘焦点、减少动态效果偏好及中英日文案同时覆盖。

## 备选与否决理由

- **从 git diff 推断本轮成果**：会把用户或其他任务已有改动归入本轮。
- **解析 bash 输出或自然语言中的路径**：不能证明文件成功生成；当前不造推测性归属。
- **新增成果数据库、模型报告协议或文件预览器**：已有消息元数据与查看能力足以支持首版，重复状态增加同步负担。
- **在卡片出现时直接运行 HTML**：打开历史会话不应触发脚本或系统浏览器。

- 不修改模型提示词、工具协议、权限、会话数据或后台任务。没有新增模型调用及上下文注入。
