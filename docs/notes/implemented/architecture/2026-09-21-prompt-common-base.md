# 模型提示词改为公共基线加专属 Delta

状态:implemented

## 问题

GPT、GLM、DeepSeek 三份模型提示词各自重复承担 RedCode 的通用工作流。它们由 `system.ts` 按模型互斥选择，导致同一条通用规则需要在多份文件维护，固定前缀也随重复文本膨胀。审计还发现，直接把专属文件缩成几句会误删模型实际需要的通用契约。

## 决策

`default.md` 作为公共基线；GPT、GLM、DeepSeek 路由改为返回 `[default.md, 专属 Delta]`，由 `session/llm/request.ts` 用换行显式合并。三份 Delta 只保留已由历史记录支持的差异：

- GPT：`apply_patch` 是真实的 GPT/Codex 工具能力，工具可用时优先用于手工编辑。
- GLM：中文 reasoning 与证据充分后的收敛。
- DeepSeek：中文且结论化的 reasoning、验证失败先重检假设、避免无关范围扩张、证据充分后行动。

其它模型专属提示词暂不迁移，避免把本次主力模型整理扩大成全量路由重构。

## 备选与否决理由

- **直接把三份文件各自砍成 Delta**：否决——当前路由是互斥选择，会丢失通用契约。
- **把所有模型提示词一次性迁移到公共基线**：否决——非主力模型缺少同等实测复核，改动面过大。
- **新增 adapter 抽象承载少量规则**：否决——Markdown + 现有路由已经足够，额外抽象没有收益。

## 后果

主力模型请求的第一段 system prompt 现在由公共基线和 Delta 组成，避免通用规则复制；模型切换路由测试需要同时断言基线与 Delta。提示词源码改动会使新会话重建首轮前缀，之后保持稳定。Delta 仍是模型可见输入，后续新增规则必须先证明属于模型特有失效模式。
