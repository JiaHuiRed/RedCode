# 前缀断裂探针转正：从「诊断完成后整块删除」到有开关有边界的常驻件

状态:implemented

## 问题

`prompt.ts` 的 runLoop 里有一块 64 行的诊断代码，注释第一行写着：

```
// 260804 Red debug probe v4 — 诊断完成后整块删除。
```

到 2026-08-19 已经半个月，不但没删，`5670d86`（同日）还给它的 key 补了 modelKey——**在长功能**。它以「临时代码」的姿态待在最热的路径上，带着四个问题：

1. **没有开关**，无条件跑。
2. **指纹表无界**：`globalThis.__prefixProbe` 是个永不回收的 Map，`5670d86` 给 key 加上 modelKey 之后条目数还从「会话数」涨成「会话数 × 模型数」。
3. **同步写盘**：`fs.appendFileSync` 直接压在 prompt 构造主路径上。
4. **日志无上限无轮转**：实测已经 1.4 MB，只会继续涨。

另有两处小的：ESM 模块里用 `require("node:crypto")`；整块夹在 850 行的 runLoop 正中间。

## 决策

**不删，转正。** 它是有用的——`5670d86` 修 prune-skip 那次，「39 次跳水吃掉 4528k 本该命中的 token、约占区间总成本 10%」这个数就是从它的日志里拿的。问题从来不是「诊断代码不该存在」，而是「它在撒谎说自己是临时的，同时无界、同步、不可关」。

抽到 `session/prefix-probe.ts`，四件事补齐：

- **开关** `REDCODE_DISABLE_PREFIX_PROBE=1`。**默认开**——哥哥的前缀缓存排查还在进行中，默认关等于静默掐掉他的数据来源。命名跟着 `REDCODE_DISABLE_PRUNE` 等既有的 opt-out flag 走。做成**按访问时求值的 getter**（同 `REDCODE_DISABLE_PROJECT_CONFIG`），否则模块加载时求值，用例和 CLI 在运行期设的环境变量都不生效——本次写用例时就踩到了。
- **指纹表接回收**：用 `util/session-evictor.ts`（同 prompt-caches / file-time / prefix-shape）。
- **写盘改异步**，并**串成一条链**：`appendFile` 之间不保证顺序，而这份日志是靠行序读的。失败一律吞掉——260804 那次硬编码 `E:` 盘路径就是这么把 prompt 构造弄崩、UI 永远「等待模型响应」的。
- **日志上限 8 MB，超了轮转一代**（`.1`）。只留一代：诊断看的是最近的断裂。

顺带把日志路径做成可覆盖（`REDCODE_PREFIX_PROBE_LOG`）。**这条是必需的**：默认路径下那份是哥哥正在用的排查数据，用例里的 `reset()` 会把它删掉。

## 备选与否决理由

- **照注释删掉**：否决——它当天还在产出诊断价值，删了下次查前缀缓存要从零重写。
- **默认关**：否决——见上，会静默掐掉正在进行的排查。
- **保留同步写**：否决——同步 I/O 在 prompt 构造路径上，且这是纯诊断，不值得占主路径。
- **日志按天切分**：否决——查的是「最近哪一轮断了」，按大小留一代足够，按天会攒出一堆没人看的文件。

## 后果

- `prompt.ts` 2251 → 2202 行。这只是把一块能独立出去的东西拿走，**runLoop 本身仍是 850 行的单函数**，结构性问题没解决，见审计清单第 8 条。
- 测试：新建 `test/session/prefix-probe.test.ts` 6 例——健康轮次只写一行不输出明细 / 真断裂报出断点位置 / **同会话切模型不报假断裂**（`5670d86` 修的那个，161 处断裂里 37 处是这么来的）/ 指纹表有界 / 开关关掉后既不写盘也不记指纹 / 日志超上限轮转（稀疏文件撑到上限，不真写 8MB）。
- 用例的 `beforeEach` 必须先 `await flush()` 再 `reset()`：写盘是异步链，不排空的话上一条用例的追加会在删完文件之后落下来，把日志重新创出来污染下一条（实测踩到）。
- 行为对外不变：日志格式、断点判据、输出条件与抽出前逐字一致。
