# TUI 首页的看板娘半格字符画——撤除，别再加回来

状态：rejected

## 问题

0.10.8/0.10.9 在 TUI 首页输入框右侧加了看板娘「赤」的半格字符画（`▀`，前景=上半像素、
背景=下半像素，22 列 × 11 行 = 22×22 像素），数据由 `packages/desktop/赤ico.png` 缩放而来。

维护者实际用起来的评价：**「这个大小几乎全是马赛克，还不如不加」**。

## 决策

整个删除：`component/chi-art.tsx`、`component/chi-art-data.ts`、`routes/home.tsx` 里的
`CHI_GAP` / `showChi` / 两处布局分支，以及一并撤掉的生成脚本。

## 为什么调整尺寸和裁剪都救不回来

做过一轮对照（同一源图、同一条管线、同一输出尺寸，只换取图哪一块与输出多大）：

| 取哪一块 | 16×8 下的结果 |
|---|---|
| 脸（原裁剪 150,170+360） | 一团浅色糊斑，读不出五官 |
| 脸（收紧到 136,162+300） | 同样糊，只是糊得更满 |
| 脸（收紧到 161,187+250） | 脸填满了，但头的剪影没了，更糟 |
| 整颗头（71,61+403） | 糊 |
| 黑猫（595,302+202） | 深色叠深色，几乎全黑 |
| **XR 标记（680,71+121）** | **清清楚楚，字母边缘锐利** |

尺寸也逐档试过（22×11 / 18×9 / 16×8 / 14×7 / 12×6）：变小只是让人不去细看，
不是让它变清楚。

结论：**问题不在尺寸也不在裁剪，在图形类型。** 同一张图里的 XR 标记在同样条件下完全可读，
而人脸、猫都不行。

## 终端半格字符画能承载什么

四条硬约束，缺一条就糊：

1. **颜色少而平。** 一个半格像素只能是一个纯色，渐变与柔和阴影会被平均成中间调，读作噪点。
2. **特征要大于 2–3 个像素。** 16 像素高的脸，一只眼睛不到一个像素，必然消失。
3. **靠剪影读。** 深底上的浅形或反之。赤的头发是深色、画面背景也是深色，剪影本身立不住。
4. **硬边缘。** 插画的抗锯齿边在缩放后全是过渡色。

赤那张是**绘画**（柔光、发丝、大片渐变），四条一条都不占；XR 标记是**图形**（平色、大块面、
硬边），四条全占。

## 备选与否决理由

- **换成 XR 标记**：否决——能读，但首页顶部已经有 REDCODE 字标，同一个 logo 出现两次。
- **只把尺寸调小**：否决——见上表，小只是让缺陷不易被察觉，不是修好。
- **手绘 16×16 像素图标**（不缩放照片，照着赤重画：黑发块、两像素红瞳、白脸）：**技术上可行**，
  这条没有被否决，只是没做——它是美术活，需要先有稿。将来若要在 TUI 放形象，走这条，
  **不要再从插画缩放**。

## 后果

- `home.tsx` 的 `useTerminalDimensions` / `createMemo` / `Show` 随之成为死引用，一并删除。
- 复发识别签名：任何「把一张插画/照片缩放成终端字符画」的提案，先按上面四条约束过一遍；
  过不了就别做。缩放照片做终端图形这条路已经验证过了，不成立。
