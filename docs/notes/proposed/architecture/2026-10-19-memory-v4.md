# Memory V4：记忆内容分层与按需读取

状态:proposed

前作:[2026-10-13 固定前缀审计建议](2026-10-13-redcode-harness-vnext-fixed-prefix-audit.md)提出「先测量、后清理、最后验证」;本 note 是其记忆部分的收敛设计,经与用户逐项对齐后定稿(2026-10-19)。实施按批次推进,每批次落地时各写 implemented note 并在此回链。

## 问题

V3 已解决「留下记录」(索引化 + supermemory.db 双写)与「查得回来」(FTS/LIKE 自动召回),这些是已验证资产,不动。剩余的是**内容存放与注入面**的结构问题:

1. **项目 MEMORY.md 兼任百科、踩坑列表与近期摘要。** 它每轮整份注入,但按寿命真正值得常驻的只有少量关键事实与触发器;成体系的设计知识在 `docs/notes/` 已有权威正文,MEMORY 里又留浓缩叙述,职责边界靠纪律维持。
2. **「上次做到哪」没有精确入口。** 近期进度混在 MEMORY 叙述里,「继续上次」时模型先猜再翻,没有可定位的进度/待办正文。
3. **文档化知识的召回是短卡缺失的全文注入。** 自动召回直接注入 DB 全文(实测 p50 328 token、p95 442),没有状态(active/superseded/rejected)与来源指针,旧结论与现行决策在模型眼里同权重。
4. **召回质量测不出漏召。** 插件只在成功注入时写 audit(`plugin/memory-recall.js`),`seed/scripts/analyze-memory-recall-audit.mjs` 只评测有 event 的消息——无命中轮次从分母消失,precision/recall 工具(2026-09-15 note)缺 miss 分母。

基线(2026-10-19 实测,本机 RedCode 会话):首轮请求实报 35,268 token;context-snapshot 估算 system ≈12.8K、工具 schema ≈19.0K(chars/4 + CJK 加权,诊断口径,非精确 tokenizer);Sol 主请求加权缓存命中 97.96%(10-14~10-18,排除 summary 请求)。**优化目标不是文件少多少字符,而是同等任务成功率下总 token/费用/耗时下降;高命中缓存里删固定前缀不等于省同量账单。**

## 决策

**V4 = V3 的内容分层与按需读取升级,不是记忆引擎重写。** 不新增 checkpoint、第二套 Todo、后台整理器或语义提取模型;公开/私有边界沿用现状(仓库 `docs/` 随 Git,项目 `.redcode/` gitignore,全局私仓按授权同步)。

### 内容归属

| 载体 | 职责 |
|---|---|
| 全局/项目 `AGENTS.md` | 必须遵守的规则与工程约束;不放事故全文与记忆操作教材 |
| 全局 `MEMORY.md` | 少量值得常驻的跨项目触发器;其余靠召回 |
| 项目 `.redcode/MEMORY.md` | 当前关键事实、少数高风险提醒、**一行当前工作路标** |
| 仓库 `docs/`(notes 等) | 可公开的架构/设计/技术决策,随项目 Git 演进 |
| 项目 `.redcode/docs/` | 私人进度、待办、环境信息(本机,gitignore) |
| 全局私仓 | 通用长期记忆与获准同步的快照(`export-memory-backup.mjs` 默认仅 global) |
| `supermemory.db` | 旧条目全文仍是权威;文档化知识的兼容检索层 |
| Todo/Git/会话历史 | 执行步骤、代码变化、原始证据,各司其职,不重复建账 |

项目 MEMORY 的一行路标格式:

```markdown
- 当前:<一句话>;进度/待办 → .redcode/docs/<topic>.md「当前进度」
```

进度正文写清:已完成、未完成、已验证结果、待决定/受阻项。优先放进已有设计/任务文档的进度节,不为每个任务新建文件。

### 读取机制

- **续接短路**:「上次做到哪/继续/待办」沿 MEMORY 路标 → 进度文档,不经过关键词召回,不算 V3 缺陷。
- **知识短卡**:文档化知识召回返回主题+结论+状态(active/investigating/superseded/rejected/archived)+来源(scope + 相对路径 + 章节)+来源版本;正文用现有 `read`(无章节 API,先搜标题再按行读,不为 V4 新造工具)。状态引用必须指向当前生效章节,文档级 implemented 不代表其内所有段落未过时。
- **召回是证据不是授权**:召回内容是低信任历史数据,旧偏好/旧方案/旧批准不得升格为当前指令;`/recall` 的「硬约束」措辞与自动召回的高权威包装在召回增强批次一并收敛。
- **失效语义**:路径缺失显式报「本机来源不可用」;旧快照只能标版本作历史参考,不得冒充现行结论;刷新失败不报成功;私有内容的摘要/索引/快照受原共享范围约束,**文档化不扩大共享面**。

### 写入分流

- 进度/待办 → 更新对应文档 + MEMORY 一行;不进长期记忆 FTS。
- 短小教训 → 维持现状(DB 全文为权威正文,值得常驻才留 MEMORY 触发器)。
- 成体系设计/决策 → 维护 docs(优先已有 notes),MEMORY 留结论与路标;文档是权威正文,DB 侧旧全文/派生快照只是兼容材料,不维护第二篇叙述。
- 首版不改 DB schema、不批量重写旧记录、不把 DB 降为纯指针。

### 预算(设计目标,非已实现)

| 项 | 预算(UTF-8) |
|---|---:|
| 全局 MEMORY | 2 KiB |
| 项目 MEMORY | 3 KiB |
| 文档短卡召回整块 | 每轮 ≤2 KiB,最多 3 条 |

含标题/来源/包装文字;超限在写入/装箱时显式提示,**不在运行时静默截断规则或半条知识**;例外走显式配置。缓存纪律:不每轮扫 docs、不热刷新 system、精简固定文本付一次前缀重建、压缩后召回行为实测。

### 实施批次

- **A 内容试点(不动引擎)**:压缩/前缀缓存/召回三主题 + 一份私有进度文档;确认入口 → 验证路标可读 → 保留 DB 全文与索引备份 → 再精简对应常驻段(先逐条核 DB 全文)。
- **B 召回增强**:短卡 + 状态/来源 + 字节预算 + 失效处理;补齐 audit 的 miss 分母(无命中轮也记录或按未注入计);保留 V3 回退。
- **C/D 后续**:批次 D 已执行。本轮限定抽查未证实知识丢失，差异仍待人工核对；不自动回填/清库，不能靠 push 消除文本差异。验收完成前不据此宣称全局索引与固定注入已通过验证。DB 规范化等大动作另立计划。

**批次 A/B 已于 2026-10-19 落地**,含漂移探针与两处召回质量修复(排名特异性、候选采样),细节与验证见 [memory-v4-batch-a-b](../../implemented/architecture/2026-10-19-memory-v4-batch-a-b.md)。

验收覆盖:续接三场景、现行/否决/调查中区分、无关任务零文档加载、压缩与重启后可召回、私有不跨项目、两机缺源显式提示、同模型同任务总账对比。回滚 = 恢复对应 MEMORY/规则文件与 V3 召回,不清旧 DB、不复用编号。

## 备选与否决理由

- **重写记忆引擎/迁移 DB schema**:否决——V3 召回与双写保护是已验证资产;第一批零 schema 改动。
- **独立任务 checkpoint/持久任务状态子系统**:否决(用户拍板 2026-10-19)——V3 项目记忆已留近期进度,一行路标 + docs 进度节足够,Goal/Todo/原始历史各司其职(`session/goal.ts`、`tool/todo.ts`、native compaction 原文可恢复)。
- **会话中热刷新 MEMORY/docs 进注入面**:否决——[2026-08-17 instruction-change-notice](../../rejected/feature/2026-08-17-instruction-change-notice.md) 已实证两轮各 ≈25 万 token 的代价。
- **所有教训强制文档化**:否决——短教训 DB 全文已是权威正文,强制搬家是把冗余复制改名;提案原文「别做的事」。
- **把 `.redcode/docs` 当全新知识库从零建体系**:否决——每日日志退役教训(0.9% 读取率)在先;优先复用 docs/notes 与现有 recall 通道。
- **精简不设上限直接砍**:否决——预算显式化,超限提示不静默截断;安全红线与不可逆操作规则不在精简范围。

## 后果

- 固定前缀收益须以批次 D 的实测与复审结果为准,不按字符数换算现金;每次精简固定文本付一次前缀重建。
- 批次 B 之前漏召率仍不可测(已知观测缺口,不隐瞒)。
- `.redcode/docs/` 不跨机同步,私有进度文档是本机的;跨机工作进度认知仍靠 Git/CHANGELOG。
- **本机 dualwrite 曾记「缺 #676–678 全文」——261019 对账实测缺 67 条**,已按对端快照全部回填、差集归零;探针(批次 A/B 落地件)防复发。

## 模型可见改动四问

本 note 是文档,不进模型上下文(docs/notes 不在注入面):模型可见内容零变化、固定前缀零增减、KV cache 不动、不适用注入上限。**实施各批次在其 commit/note 逐条回答四问**——MEMORY 精简与召回短卡都是模型可见改动,届时单独作答。
