### RC-03 · P1 候选 · Native compaction 目标预算公式待验证（重要但未证实）

**证据**

- `native-context.ts:82–121`
- `compaction.ts:467–553`
- `native-context.test.ts:94–123`
- `context-compaction.ts:346–430`

**疑点逻辑**

```ts
const measured = messages.reduce((total, message) => total + measure(message), 0)
const total = currentTokens > 0 ? currentTokens : measured
const scale = currentTokens > 0 && measured > 0 ? total / measured : 1
const floor = messages.reduce((sum, message) => sum + retained(message), 0) * scale
const required = Math.max(summaryMaxTokens, total - floor - targetTokens + summaryMaxTokens)
```

当前测试已验证 `total=100,000` / `floor=40,000` / `target=40,000` / `summary=16,000` 时 `required=36,000`、选中 18 条消息；但**没有直接验证提交后的完整下一轮请求是否真的降到 `target=40,000`**。

如果保护记录压缩后仍完整出现在最终模型输入中，按抽象 token 守恒估算，`100k - 36k + 16k ≈ 80k`，会高于绝对 target。这里可能是**公式目标口径（可回收部分 vs 总上下文）不一致**，也可能有模型消息投影、固定前缀和实际保护预算收束带来的差异。因此此项是**必须实测的候选缺陷，不是已证明的线上 bug**。

**先加回归，不要凭直觉回滚**

1. 构造新消息、已消费摘要锚点、受保护 user/tool 输出、部分过大需退回读的记录和固定系统前缀。
2. 从 `planAutomatic` → `ContextCompaction.commit()` → 下一轮 `NativeRuntime.project()` → 最终发送 `modelMessages`/完整请求估值**贯通测试**。
3. 单独记录 `preTotal`、`irreducibleFloor`、`released`、`summary`、`postActual`、`target`、是否 shortfall；**不要用选段条数代替发送请求大小**。
4. 若 `postActual > target` 且并非"目标物理不可达"，修正绝对预算数学和含前缀的单位换算；若不可达，明确输出"目标未达到 / 保护量刚性占用"，**防止被标记成成功降至目标**。
5. 跟进重复压缩 / 高缓存损失场景；保持原始历史可回读、protect 优先级、严格 import、单次 revision settle、DCP/native 互斥等既有契约。

**验收**

普通 / 保护量很大 / 全部不可回收 / 多个旧块 / 短缺降级**五类用例**；有实际 `postActual` 与 `target` 对照，短缺有明确告警；不出现"连续压缩几次，下一轮仍接近触发线"而没有说明的情况。若推演被证伪，在验收记录中附真实投影数值，**不需改生产代码**。

### RC-05 · P2 · Codex turn-state 未按账号隔离（风险待复现）

**证据**

- `plugin/codex.ts:42–49`：`turnStates` 为进程级 `Map<string, string>`，最大 512 项。
- `plugin/codex.ts:475–590`：OAuth 授权账号可变，取/存 turn token 只用 `x-redcode-turn`。
- `session/llm/request.ts:199–229`：key 用 session、user、agent、wire model 的 hash，**不含 account ID**。

最新修复解决了标题与主对话串用；**同一 turn 的账号重新授权/切换仍可能复用旧 token**。单账号、同 turn 场景下不等于实际出错；需要模拟切换。

**操作**

对账号变化时的 map 清理或账号维度复合键做最小修复；**不可将 access/refresh token 原文用于日志或 map key**。覆盖标题与主对话并发、同链首 token 不覆盖、跨 turn / session / agent / model / account 不复用，及既有同链复用语义。

**验收**

真插件 + 本地 HTTP 回归；账号 A 的 turn-state 绝不发送到账号 B；不改变请求正文、不额外注入固定前缀、不记录敏感原文。

## 3. 这次值得保留的好设计（不要"修复"回退）

1. **Codex 请求链隔离**：`codexTurnKey([sessionID, userID, agent, wireModelID])` 使标题/压缩摘要和主对话不再抢相同 first-response token；只在 OpenAI OAuth 路径加相应头。
2. **最终 wire 模型路由提示**：`x-codex-routing-hint` 从最终序列化 body 的 `model` / `service_tier` 推导，不猜 model tier、不改请求正文；输入不支持时 fail-open 让供应商处理。
3. **供应商缓存取证三态**：`reported` / `reported-zero` / `missing` 分开；匿名 HMAC 只记白名单头，不落 OAuth 凭证、账号和请求正文原文；GUI WARN 日志级别能够真正留存证据。
4. **Native 历史数据安全**：保留原文回读、严格导入、保护记录共享预算、从旧块降级回账本、排除 queued user 与 running tool，DCP 与 native 互斥。
5. **测试口径诚实**：提交记录"43 个定向测试通过"与"真实缓存/额度收益仍待验证"没有混淆。下一步是补完整请求和 Windows CI，而不是替换此原则。

> **缓存解释注意**：曾出现 51,618 和 100,414 input token 全 miss（仓库内 `2026-10-13-codex-routing-affinity.md` 记录）；新版客户端隔离能解决**已复现的标题令牌抢占**，但**不能宣称缓存归零已根治**、也不能从 CI 契约测试推断真实订阅额度收益。必须用重编重启后的真实 provider usage 和请求链指纹做 A/B 对照。
