# RedCode TUI 多项目工作区切换：功能审计与实施任务书

审计基线：`6948d23f6ae3`

依据：上传的 `RedCode-6948d23f6ae3-source.txt` 与三张 TUI 使用截图。

审计方式：静态源码分析与交互方案设计；未运行 Windows EXE，未修改仓库，未验证跨项目后台任务的实际生命周期。不将此快照称为 GitHub 最新版本。

目标：启动直接进入 TUI 首页；点击输入框上方的工作区路径，在同一个窗口内切换或添加项目，并恢复各自的会话与草稿。

**给开发 Agent**：先对照当前 checkout 核实本文定位，再实际实现。本文中的架构与行为要求是建议方案，不是对现有能力的宣称。

> 整理说明：原稿中重复出现的源码引用标记已统一收敛为上方「依据」，正文不再逐处重复；其余内容、措辞与判断均保持原样。

## 1. 审计结论

建议实施。这是一次改变日常工作流程的功能升级，不只是给路径文字增加点击事件。

当前使用流程是：

> 打开 EXE → 选择工作区 → 在该项目内工作 → 处理其他项目时再开一个 EXE。

目标流程是：

> 打开首页 → 点击工作区路径 → 选择其他项目 → 在同一个 TUI 内继续工作。

总体工程量判断为中等偏上。选择弹窗、路径点击和最近项目列表较简单；主要工作集中在项目状态作用域、请求归属、界面恢复，以及「切换视图不终止原任务」。这不是工期估计。

本次交付应当做到：

- 一个前台界面可以在多个项目之间往返，不要求多个项目的完整界面同时挂载。
- 不先扩展成多标签 IDE，也不新增通用任务调度平台。

### 术语必须区分

界面可以继续沿用用户熟悉的「工作区」。但代码层面应区分：

| 概念 | 本文含义 | 示例 |
| --- | --- | --- |
| 项目目录切换 | 切换到另一个独立目录下工作 | `E:\AI\RedCode` → `D:\KLX\CWB\dossier` |
| 现有 Workspace / Worktree | 现有实验性工作区体系及其会话迁移能力 | `workspace.current()`、`experimental.workspace.warp()` |
| 会话切换 | 在所属项目内查看另一段对话 | 同一项目中的会话 A → B |

本任务是第一种，不应通过迁移旧会话、复制 Git 修改或给旧模型追加「换目录」指令来实现。

## 2. 已确认的源码现状

下列定位来自上传快照。涉及聚合文本行号时，指的是 TXT 中的行号，不是仓库内单文件行号。

### 2.1 工作区选择发生在 TUI 启动之前

`packages/opencode/src/cli/cmd/tui/thread.ts` 的启动逻辑在未提供项目参数时调用：

```ts
ProjectSelector.selectProjectInteractive()
```

随后执行 `process.chdir(next)`，创建 `Worker`，再把 `directory: cwd` 交给 `tui()`。

**判断**：目前是启动时选择目录，不是运行中的跨项目导航。仅删除启动选择器，并不会自动获得热切换能力。

### 2.2 路径标题已有，点击入口尚未接入

`packages/opencode/src/cli/cmd/tui/component/prompt/index.tsx` 已经有项目名、路径与分支组成的标题行，但这段标题 JSX 尚未绑定项目切换事件。

**判断**：无需重新设计输入框。沿用现有标题行即可形成自然入口。

### 2.3 SDK 初始化时绑定目录，不能只更新显示文本

`packages/opencode/src/cli/cmd/tui/context/sdk.tsx` 在初始化时建立客户端：

```ts
createOpencodeClient({
  baseUrl: props.url,
  signal: abort.signal,
  directory: props.directory,
  fetch: props.fetch,
  headers: props.headers,
})
```

同一 Provider 还管理事件订阅、请求取消信号和清理。

**判断**：界面上的目录、请求实际使用的目录以及项目状态必须一起切换。单独改变标题或调用 `process.chdir()` 不构成完整方案。

### 2.4 同一个 Worker 有可复用的请求与事件通道

`thread.ts::createWorkerFetch()` 转发请求 URL、method、headers 和 body；`worker.ts::rpc.fetch()` 将这些请求交给 `Server.Default().app.fetch()`。Worker 同时把 GlobalBus 事件转发为 `global.event`。

**判断**：已有通道为「同 Worker、不同目录客户端」提供基础，不必默认每个项目创建一个 Worker。

但服务端目录实例分发、任务取消及实例回收代码未在本轮完整核实，必须通过两个临时目录的实际调用确认。

### 2.5 现有 Workspace 选择器不能直接当成跨项目切换器

`component/dialog-workspace-create.tsx::warpWorkspaceSession()` 会调用 `experimental.workspace.warp()`，可携带 `copyChanges`，还会向同一个会话添加 synthetic reminder。

`context/project.tsx::workspace.set()` 修改的是现有 Workspace ID。

**判断**：可以借鉴其弹窗风格，但不能复用这条业务执行路径切换 RedCode 与 dossier。

### 2.6 重新挂载整棵 App 有额外副作用

`app.tsx` 中包含 `TuiPluginRuntime.init()`、快捷键注册与启动参数处理；`routes/home.tsx` 中有 `--prompt` 自动发送逻辑。`config/tui.ts` 还会按目录查找项目级 TUI 配置及插件来源。

**判断**：不能简单给整个 App 加一个目录 key，反复重挂就算完成。

必须区分全局资源、项目状态与只执行一次的启动动作；也不能把所有现有 TUI 配置未经分析就改成全局配置。

## 3. 第一版应交付的用户体验

### 3.1 默认启动直接进入首页

保留现有 Logo、Soul、输入框、主题与背景。

取消默认启动前的全屏工作区选择页，但保留其「发现项目、选择目录」的能力，改为首页内随时打开的弹窗。

启动目录按来源解析，不使用一个不分场景的「上次项目永远优先」规则。

| 启动方式 | 建议行为 |
| --- | --- |
| `redcode <path>` | 使用明确指定的目录；无效时报告，不悄悄换项目 |
| 在真实工作目录中运行 `redcode` | 尊重调用位置；不能被上次项目覆盖 |
| 双击 EXE／快捷方式，启动位置落在已识别的程序安装目录 | 优先恢复上次成功使用且仍有效的目录 |
| 没有可靠目录，也没有可恢复记录 | 显示首页与「未选择工作区 · 点击选择」，允许输入草稿，但选择成功前不发送 |
| `--session`、`--continue`、`--fork`、`--prompt` | 保持命令行意图；明确目录与会话不匹配时给出原因，不自行迁移会话 |

程序安装目录不能仅凭文件夹名叫 `bin` 来判断，应结合实际可执行文件位置或已有启动来源信息。无法可靠辨别时，不猜测用户目标；明确路径参数始终优先。

**「启动首页」与「恢复项目」也要区分**：默认进入所选项目的首页，不因为保存了最近会话就擅自触发继续执行。用户主动切换项目时，可以恢复该项目上次查看的会话。

### 3.2 路径标题成为统一入口

将输入框上方的「项目名 + 路径」区域设为可点击，增加轻量下拉指示及悬停反馈。首页和会话页使用同一个入口、同一种弹窗。

同时在命令面板提供「切换工作区」。建议内部命令名为 `project.switch`；快捷键在检查现有绑定后确定，不覆盖已有按键。

继续保留右侧分支显示。选择文字或复制路径时不要误触切换。关闭弹窗后回到原输入框及光标位置。

### 3.3 弹窗先展示可用项目，再补充信息

弹窗首屏显示当前项目、最近项目和「添加工作区」。项目名称下方显示可辨认的路径；同名项目靠路径区分。

支持现有 TUI 风格的键盘搜索、方向键、Enter 确认及鼠标选择。

先展示已有项目元数据，**不能为了列出历史项目，就逐个初始化这些项目的 MCP、LSP 或文件监听器。** 运行状态不是必需的首屏依赖，已有可信摘要时再显示。

复用现有 `DialogSelect` 和项目数据来源。

**不得在 OpenTUI 正在运行时直接调用旧 `selectProjectInteractive()`。** 旧实现自行接管 raw stdin、ANSI 清屏和鼠标协议，清理时还会移除 stdin 的 data listeners，不是可直接嵌入的弹窗。

### 3.4 「添加工作区」先只表示打开已有目录

第一版提供路径输入，确认目录存在且可访问，成功后加入最近项目并切换。中文和含空格的路径应正常工作。

这一步不默认创建目录、不自动 git init、不生成 Worktree、不安装依赖。

失败保留用户已输入的路径，并允许取消回原项目。

### 3.5 切回项目，应当像回到刚才的工作现场

从 A 切到 B，再返回 A，应恢复上次查看的会话或首页、未发送草稿、附件引用和基本阅读位置。没有历史会话的项目进入首页。

A 的草稿留在 A，不能跟着输入框被带进 B。

恢复会话只是查看，不自动发送、重试或继续生成。

## 4. 推荐实现边界

### 4.1 保留一个 TUI 外壳，只切换当前项目作用域

推荐的职责划分如下；这是目标结构，不要求逐字照搬命名或立刻新建大量模块。

| 层级 | 职责 | 切换项目时 |
| --- | --- | --- |
| 常驻外壳 | Renderer、终端输入接管、退出流程、现有 Worker／连接、全局命令与通知入口 | 保持，不重新启动 EXE |
| 项目导航管理 | 当前目录、最近项目、项目视图快照、正在切换的目标 | 更新选择，保存／恢复快照 |
| 当前项目作用域 | 目录绑定 SDK、项目配置、会话与消息状态、编辑器上下文 | 重新绑定或按作用域重建 |
| 后台摘要 | 已访问项目的任务状态、待处理确认等轻量信息 | 按原归属更新，不依赖当前画面 |

一个可接受的第一版是：

只挂载当前项目的重型视图，其他项目保留轻量快照，后台任务仍由原服务端实例运行。

不要求所有项目组件永久保活。

### 4.2 项目、会话与启动动作分开存放

项目记录至少保存目录标识、显示名称、最近使用时间和上次查看的会话。草稿按「目录 + 会话 ID／新会话」区分，不使用一个全局草稿覆盖所有项目。

目录身份使用仓库现有路径规范化规则。多连接场景还需区分服务器；不能只靠项目显示名或 projectID 代替目录。

路由可以显式携带目录，也可以由外层项目作用域绑定，不强制重写整个 Route 类型或插件路由协议。

`--prompt`、`--fork`、`--continue` 等属于启动动作。它们是否已消费的状态必须跨项目切换保留，不能因为组件重新挂载而再次发送、分叉或跳转。

### 4.3 保留配置和插件的原有归属语义

项目级模型配置、Agent、命令、权限策略、MCP 等应跟随目标项目生效；不能让 B 继续误用 A 的配置。

TUI 主题、键位、插件等既可能来自全局配置，也可能存在项目覆盖。实现前根据现有解析规则划分归属：

- 能就地更新的配置就地更新；
- 目录作用域插件按实际生命周期处理；
- 必须重启才支持的配置应明确提示，不能假装热更新成功。

常驻插件若捕获了旧 SDK 或 Sync，需要提供正确的当前项目访问方式，或执行一次清理明确的项目级重绑定。不要为此重写全部插件系统。

## 5. 一次切换应如何完成

建议采用**「准备目标 → 提交切换」**的流程，而不是用户一点就先清空当前界面。

### 准备

读取目标目录，检查可用性；界面显示「正在切换到 dossier」。

保留当前内容和退出操作，不清屏。切换期间暂不发送新需求，避免画面与实际请求目标不一致。

### 保存

提交切换前，保存源项目当前路由、完整草稿、附件引用与阅读位置；哪怕草稿只有一个字也需要保留。

尚在进行的附件处理绑定原草稿归属，不能完成后写进目标项目。

### 绑定

为目标目录建立正确的 SDK／项目上下文，获取目标项目身份与必要配置。

首次访问只加载开始工作必需的信息，不等待所有辅助状态和历史会话全部加载。

### 提交

目标可用后，一起更新路径标题、会话视图和输入目标，恢复目标草稿及焦点，记录本次成功使用的项目。

旧异步回调只能写回原作用域，不能覆盖当前项目。

### 失败

目标不可用时保留或恢复源项目，显示具体原因。最近项目不能被一次失败的切换改成无效路径。

连续选择 B、C 时，以最后一次有效选择为准；无需为此设计复杂调度系统，使用项目作用域标识或切换代次即可。

不要把多项目切换实现成反复 `process.chdir()`、重新启动 Renderer，或每个目录创建一个新 Worker。

所有项目敏感的文件读写、Shell cwd、搜索和配置解析应从其所属目录获得上下文。确实依赖全局 cwd 的调用点应逐一改为显式目录，而不是隐藏在一个新的全局变量后面。

## 6. 后台任务：切换视图不等于停止工作

第一版完整验收应包含这一场景：

> A 正在执行任务，用户切到 B 发送另一项需求，随后返回 A 查看结果。

目标行为是：A 的工具继续在 A 执行，B 的需求只进入 B；切换项目不调用 `worker.shutdown`、`global.dispose`、实例全量销毁或任务取消。

源码中 `worker.ts::shutdown()` 会销毁全部实例，`reload()` 也包含实例全量处置，因此这些入口不能被拿来模拟项目切换。

不过，**「客户端不主动取消」并不能单独证明任务会继续。** 本轮没有完整验证服务端请求断开、Fiber 归属和实例回收的行为。

开发时必须先跑通真实任务再宣称支持；若尚不成立，应保留可用的空闲切换，并明确运行中切换未完成，而不是把自动停止包装成完整多项目能力。

### 6.1 返回项目时补齐状态

现有 `useEvent()` 按 global 或当前项目 ID 过滤事件；`sync.session.sync()` 对已记录为完整同步的会话会直接返回。只修改「当前项目」标识，有可能让离开期间的消息没有进入对应视图，返回时又没有补拉。

建议复用现有 reconcile／快照能力处理重新进入后的补齐，或由目录分片的同步状态持续接收事件。

无需为了第一版引入整套事件日志系统。

### 6.2 其他项目的待确认事项不能消失

A 在后台等待权限或提问时，提供轻量提示，例如「dossier 等待确认」，并允许回到所属会话处理。

不用新增大型活动面板，也不把 A 的权限弹窗直接套在 B 的输入框上。

确认和取消操作必须使用原请求所属目录及 Workspace，不按照当前画面猜测归属。既有跨 Workspace 请求归属记录应保留。

### 6.3 区分切换、移除记录与退出应用

切换是改变查看对象；从最近列表移除只是移除入口；真正退出应用沿用现有任务退出行为。

本任务不承诺关闭 EXE 后任务仍继续运行，那是另一项后台服务能力。

运行中或等待确认的项目不能被当作普通闲置缓存顺手销毁。也不要为显示最近项目而提前初始化所有目录。

## 7. 建议修改位置与实施顺序

### 7.1 源码定位

以下均是调查入口，不要求每个文件都修改。

| 位置 | 本任务中的职责 |
| --- | --- |
| `packages/opencode/src/cli/cmd/tui/thread.ts` | 取消默认强制选择，解析启动目录，保留原 Worker 生命周期 |
| `packages/opencode/src/cli/project-selector.ts` | 拆出／复用项目元数据，不把 raw stdin 界面嵌入 TUI |
| `packages/opencode/src/cli/cmd/tui/app.tsx` | 区分常驻外壳与项目作用域，注册切换入口，管理一次性启动动作 |
| `packages/opencode/src/cli/cmd/tui/component/prompt/index.tsx` | 路径点击、完整草稿保存恢复、切换期间发送行为 |
| `packages/opencode/src/cli/cmd/tui/context/sdk.tsx` | 请求目录绑定、事件和请求生命周期 |
| `packages/opencode/src/cli/cmd/tui/context/project.tsx` | 当前项目身份与目录更新；不要混用 Workspace ID |
| `packages/opencode/src/cli/cmd/tui/context/sync.tsx`、`event.tsx` | 项目状态隔离、返回后的补齐、后台摘要与请求归属 |
| `packages/opencode/src/cli/cmd/tui/context/route.tsx`、`routes/home.tsx` | 恢复视图、无项目首页、启动动作只消费一次 |
| `packages/opencode/src/cli/cmd/tui/config/tui.ts`、插件运行时 | 核实项目配置覆盖与插件重绑定 |
| `packages/opencode/src/cli/cmd/tui/worker.ts` 及完整仓库中的服务端实例代码 | 验证共享 Worker 多目录请求与后台任务不被切换终止 |

新增项目管理与项目选择弹窗模块可以采用 `project-manager.tsx`、`dialog-project-select.tsx` 等名字，但优先服从仓库现有组织，不建第二套同义状态系统。

### 7.2 三个可交付批次

#### Batch A：先跑通同窗口的真实切换

先用两个临时目录验证现有 Worker 的显式目录请求，再接入路径点击与选择弹窗。

实现空闲状态的 A → B → A，确认标题、请求目录、项目配置和会话列表一致。

不要先花大量时间扩建配置或测试框架。

#### Batch B：完成日常使用流程

取消默认启动选择页，落实启动目录规则；添加已有目录；恢复会话与草稿；处理失败返回、焦点及启动参数的一次性消费。

完成后，用户日常往返不再需要第二个 EXE。

#### Batch C：完成运行中的切换与体验验收

验证 A 工作时切到 B，再返回 A；补齐后台待确认提示和返回后的状态刷新。

检查热切换是否重复初始化全局资源，录制连续使用流程。

## 8. 验收：以实际操作为主

| 场景 | 必须看到的结果 |
| --- | --- |
| 双击 EXE，已有可恢复项目 | 直接出现首页，不再出现启动前选择页，不误入安装目录 |
| 在项目 B 的终端中启动；上次使用的是 A | 尊重调用位置进入 B；显式路径参数同样优先 |
| 点击路径与命令面板入口 | 打开同一选择器，当前项目清楚，搜索和取消顺手 |
| 添加中文／含空格目录；输入不存在的目录 | 有效目录可进入；无效目录保留输入并解释原因，不丢源项目 |
| A 输入文字并附带文件，切 B 再回 A | 草稿及引用仍属于 A；B 不出现 A 的输入 |
| A、B 设置不同项目配置并各发一条需求 | 会话、配置及实际文件访问均落在正确目录；不是只检查标题 |
| A 执行中的任务，切到 B 开工，再返回 A | A 未因切换被取消，B 不受 A 事件污染，A 状态可恢复 |
| A 后台等待权限 | 能看到所属项目提示，回去处理；回复不被发到 B |
| 使用 `--prompt`／`--fork` 后往返项目 | 启动动作不重复执行 |
| 多次 A → B → A；退出并重开 | Renderer／Worker 不因切换反复创建；最近项目记录有效；退出行为未被悄悄改变 |

前六项以实际客户端操作为主；事件路由、一次性动作与草稿归属补最小回归测试。

不要用纯函数测试通过替代真实切换验收。

性能记录只关注用户能感觉到的几个阶段：选择器可见、选定项目后标题与内容一致、输入框可以发送、返回已访问项目所需时间。

区分首次访问与返回访问，分别记录实测值；未测就写 `not_measured`，不预设提升比例。

## 9. 本次不做什么

不做完整多项目标签栏、不重写 GUI、不增加新任务调度器、不为历史项目批量预热、不自动迁移会话或代码修改，也不将 TUI 重构成新的全局状态框架。

第一版以本地 TUI 和用户的 Windows 使用流程为目标。现有 attach 不应被破坏；远程新增目录、远程路径浏览和多服务器热切换不纳入本次完成承诺。路径校验不能把远端目录当作本地目录处理。

只处理与本功能直接相关的正确性：

> 请求不能发错、草稿不能丢、任务不能被误停、切换后必须能继续工作。

无关的旧问题另记，不借这次功能扩张范围。
