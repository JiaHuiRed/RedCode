# 记忆：写侧 + 剪枝

| 层       | 文件                          | 写什么                             |
| -------- | ----------------------------- | ---------------------------------- |
| **项目** | `<项目根>/.redcode/MEMORY.md` | 本项目的进度、坑、决策、关键路径   |
| **全局** | `~/.redcode/MEMORY.md`        | 跨项目通用教训（过三道门禁才提拔） |

机制主位在本 skill——写侧落笔、编号、双写、剪枝、跨机恢复都在这里；全局 `AGENTS.md`「记忆系统」节只保留每轮需要的触发器（双层叠加注入、索引化、注入面纪律、收工流程），冲突时以本 skill 为准。

> **260902 合并**：原 `memory-automation`（写）与 `consolidate-memory`（整理）合成一份。
> 分开时写侧每轮强制注入、整理侧只在被叫到时才 load，结果是**只写不剪、注入面单调上涨**。
> 现在两条都不注入（`instructions` 已摘掉），合并没有每轮成本，且剪枝挂在了写的路径上。

## 0. 写之前先看要不要剪 ⚠

**MEMORY.md 每轮整份注入。只增不删 = 每轮成本单调上涨，一条啰嗦的教训不是花一次钱，是花到删掉它为止。**

准备追加之前先量一下：

```powershell
# 量**字符**（UTF-16 码元）。⚠ wc -c 量的是字节：中文每字 3 字节虚高 60%+，
# 261013 实测全局 MEMORY 12,744 字节只有 6,820 字符——按字节判线会误触发剪枝。
(Get-Content -Raw ~/.redcode/MEMORY.md).Length    # 全局
(Get-Content -Raw .redcode/MEMORY.md).Length      # 项目（在项目根跑）
```

- **全局 > 12000 字符** → 先走下面第 5 节剪一轮，再写新条目
- **项目 > 8000 字符**，或超过 AGENTS.md 收工流程写的 30 行 → 同上
- 没超就直接写，别为了"顺手整理"占用正常工作的工具调用

阈值按**字符**不按条数：索引行是一行打包多条（`- 协作与沟通：#96 … | #91 … | #72 …`），
数条数会得出"73 条早就超了"、数行数会得出"49 行远没到"，两个都不反映真实成本。
字符数才是每轮真付的那笔。

## 0.5 记忆写入五问（写之前逐条自问）

权威版在此（全局 `AGENTS.md` 只留一行指针）；落笔前逐条过：

1. **换个项目还成立吗？** 不成立 → 只写项目记忆，别塞全局。判据：把项目名/仓库名/文件路径从句子里抽掉，还读得通吗。
2. **忘了会再踩、且代价不便宜吗？** 一次试错就明白的、一 grep 就查到的、`--help` 看一眼就知道的 → **不写**。
3. **规则面或机制已经覆盖了吗？** AGENTS.md / soul / skill 里已有的**不写**（那些往往写得更细）；hook 与权限请求能拦的**不写**——记忆买不到额外安全，最终决定权在用户手里。
4. **是教训，还是状态？** 进度、待办、某次实验的数字、正在做但还没结论的事 → **状态，不进长期记忆**（进度查 git，数据查日志）。
5. **这坑犯过几次了？** 复发 2 次 → 归正式分区、标注复发，并回答"机制上怎么拦"（答不出也写明"待机制化"）；**3 次以上必须机器门禁**（启动校验 / CI / pre-commit 拦截），记忆只留指针——写了还犯的记录证明：**别指望任何注释、记忆或一次性提示能拦住惯犯**（案例：DCP 触发线键漏配五犯 → 启动对账；hashline 缩进两犯 → 落盘必 diff）。

**答「不确定」默认不写**——宁可漏（下次再踩还能补），不可滥（每轮都在付）。

与「模型可见改动的四问」同一种纪律：写之前先把**「这东西凭什么占固定前缀」**答清楚。

## 1. 过了五问，这几类立刻写，不等收尾

1. 被纠正 / 犯错 → 错在哪 + 正确做法
2. 项目决策 → 用户定了"用 X 不用 Y"
3. 本项目特有的坑 → 现象 + 根因 + 绕法

## 2. 双写动作（缺一不可）

① MEMORY.md 加索引行：4-8 字主题 + 关键动作词，放对应分区；全局条目编号 = **当前最大号 + 1**。查号口径（261011 修订）：**先 `bun ~/.redcode/scripts/next-memory-id.mjs` 查 db**——编号在 INSERT 时即占用，MEMORY.md 索引行滞后于库，同机并行会话已实测撞号；跨机再 fetch 私仓比对 origin 的 `memory/lessons-backup.*.md` 快照，取两者最大。只 grep MEMORY.md（本地或远端）都会漏（261011 #320 实证；旧版让 grep MEMORY.md 的命令已废）
② db 存全文：`sqlite_query` 对 `~/.redcode/supermemory.db` 执行
`INSERT INTO memories (content, project, source) VALUES (全文, 'global'|项目名, 'manual')`
③ 核对：`bun ~/.redcode/scripts/check-memory-dualwrite.mjs`（私仓 pre-commit 也会拦，别 `--no-verify` 带病闯关）

**content 首行格式**（核对脚本与召回展示都靠它）：

- 全局：`#NN 标题（YYMMDD）`——编号与索引行严格一致
- 项目：`[项目名·踩坑|决策|技法] 标题（YYMMDD）`——不编号，靠标签分类

## 3. 取全文

索引行只有主题、没有细节。要细节：先看最新 user 消息尾部有没有 memory-recall 的注入块，没有就 `/recall <关键词>`，或直接查库——
`SELECT content FROM memories WHERE content LIKE '%关键词%'`（FTS 走 `memories_fts MATCH`，短词用 LIKE）。**别凭索引行猜。**

## 4. 边界

- 追加用 read + edit，**绝不用 `write`**（覆盖整个文件）、绝不用 `echo >>`（Windows 中文变 GBK，redline-guard 会拦）
- 会话内改记忆本会话不生效：system prompt 第一轮已缓存，记忆是写给下一个会话的
- 两层语义正交，同一条不要两边都写
- 删索引行前先确认 db 有全文——索引行是唯一入口，库里没全文就真丢了

# 5. 整理（剪枝）

> **索引化前提（260813 修订）**：两份 MEMORY.md 的教训/决策只有索引行，**全文在 `~/.redcode/supermemory.db`**。整理时的删除动作分两种，去向不同：
>
> - **删"过时进度段落"**（项目记忆）：整段原文挪进 `<项目根>/.redcode/MEMORY-archive.md`（本地归档文件，没有就建）。**进度不入 db**——它是时效性内容，进召回库只会在几个月后当噪声弹出来；段落里若埋着可复用的教训/技法，把那部分**单独蒸馏成条目**入 db（参照 260813 做法：进度归档 + 蒸馏 4 条入库）
> - **压缩/删除教训条目索引行**（两份都适用）：删索引行前先确认 db 有全文（`SELECT COUNT(*) FROM memories WHERE content LIKE '#NN %'`），没有就先 INSERT——**删索引行 = 删除唯一入口，db 里没全文就真丢了**（260813 实证：#102/#103 索引在、全文只在另一台机器，召回必 miss）

260807 实测：全局记忆 29 条从 13.4k 压到 7.3k 字符，砍掉 45%，**一条没删**。

放心在会话中途整理：记忆在开局第一轮就已读盘并进了 system prompt，改文件不会重新加载、不动本会话的前缀缓存（这是刻意设计）。收益从下一个新会话开始兑现。

## 两层规矩不同

|             | 全局 `~/.redcode/MEMORY.md`  | 项目 `<项目根>/.redcode/MEMORY.md`         |
| ----------- | ---------------------------- | ------------------------------------------ |
| 教训 / 决策 | **一条不删**，只压缩、只归类 | 同左                                       |
| 进度段落    | 不该出现                     | **久远且已完成的删掉**（先归档再删索引行） |
| 编号        | 只增不复用，整理时**不重编** | 一般不编号                                 |

## 流程

### 5.1 先读全文

`read` 整份文件。整理是全局重排，不是局部修补——没读完就动手必错位。

### 5.2 旧格式检测

读完后先判断格式：正文是**完整段落全文**（没有 `- #NN` 索引行，条目以长短句/标题开头）→ 旧格式存量项目。**先索引化再整理**：每条教训全文 INSERT `supermemory.db`（project=项目名，content 首行 `[项目名·踩坑|决策] 标题（YYMMDD）`）+ 正文改写成索引行（4-8 字主题 + 关键动作词），全部转完再走下面的归类压缩。新格式（索引行结构）直接跳过本节。**不做跨项目一次性迁移**——只在该工作区整理或收尾时发现了才就地转；新项目不受影响（播种模板已带索引化指引）。

### 5.3 盘点结构问题

常见五种：

- **插错位置**：新条目插在文件头或某个分区中间（编号不连续处就是嫌疑）
- **重复标题**：同一个 `# 历史教训` 出现两次
- **同主题散落**：三条 PowerShell 坑躺在文件三个不同位置
- **叙事冗余**：一条教训写六行，真信息只有"现象 + 命令 + 守则"三句
- **引用已消失**：条目里的路径、commit、外部工程或配置项若已不存在，就该删掉——但只删**核实过确实没了**的，别凭"看着像过时"下手

### 5.4 归类：按主题，不按时间

时间顺序对召回毫无帮助——查的时候问的是"这属于哪类坑"，不是"这是哪天记的"。全局记忆现行分区（260807 定）：

工作方法与协作 / 验证方法论 / 代码修改与诊断守则 / 语言与运行时坑 / 前端渲染坑 / Windows 平台 / 网络与代理 / 前缀缓存 / RedCode 配置与 MCP 排查

**编号绝对不动**。条目在会话和 commit 里按号引用（"教训 #76"），重编号会让所有历史引用失效。归类只挪位置。

### 5.5 压缩：砍叙述，留指纹

每条只留两样：**坑的识别签名** + **守则/修法**。

必须保留（召回时真正要用的）：

- 命令、路径、文件名、行号锚点
- 报错原文与特征串（`EADDRINUSE`、`Cannot find module`、`content is required`）
- 阈值与数值（`timeout: 120000`、`miss>3k`、`0.2..10`）
- 判定法——怎么确认是这个坑而不是另一个

砍掉：

- 心路历程（"我当时以为…后来发现…"）
- 前车案例压成括号半句：`（前车：RedClash 实际在 D:\AI\KLX\Qiu\RedClash，白找 4 轮）`
- 与守则重复的现象复述

### 5.6 立暂存区，防止下次又插错

文末留一节：

```markdown
## 新增暂存（新教训追加到本节末尾，整理时归入主题分区）

（暂无——新条目直接加在本行之下）
```

第 2 节的追加姿势（read → edit 最后一行）天然落到这里，不会再插进文件头。

### 5.7 验证（必做，260813 换了口径）

整理 = 整文件重写，**只看 diff 不算验证**。⚠ 索引化后条目是 `- #96 主题 | #91 主题` 索引行，
**不再有 `### NN.` 标题**——老的数标题法会数出 0，别再用。现在的不变量是：

> **索引引用集合 ⊆ db 全文集合**（260813 实证过缺口：索引有 #102/#103、库里没全文，召回必 miss）

- **全局**：从 MEMORY.md 提取全部 `#\d+` 去重 → 逐个核对 db 有全文
  （`SELECT COUNT(*) FROM memories WHERE content LIKE '#NN %'`，为 0 就是缺口，先补 INSERT）
- **引用数与整理前必须相等**（教训一条不删；只允许"合并进别的编号"且原编号在合并目标里注明）——⚠ 这条只约束**整理**；索引层审计（第 6 节）有意减少引用数，不受它约束
- **项目**：挪进 `MEMORY-archive.md` 的段落数 = 归档文件本次新增段落数；蒸馏入 db 的条数
  用 `SELECT COUNT(*) ... WHERE project='<项目名>'` 前后对比核对
- 字符数前后对比，确认真的压缩了——**并回到第 0 节的阈值确认已降到线下**

### 5.8 导出快照 + 提交

**先重导备份快照**（整理动了库就必跑，一步都不能省）：

```bash
bun ~/.redcode/scripts/export-memory-backup.mjs
```

`memory/lessons-backup.<机器名>.md` 是**入库推送**的——全文的版本化（防篡改/写坏可回滚）与
跨机可见全靠它；db 本身 gitignore，不导出快照，这次整理的全文变化就没有 git 历史。

然后 `git pull --rebase`（`~/.redcode` 是私仓，可能有别处刚写的），add 改过的文件 + 快照，
**不 `add -A`**。项目记忆跟项目自己的仓库走，不进 `~/.redcode`（项目的 `MEMORY-archive.md`
在 `.redcode/` 下通常也被项目 gitignore，属本机文件）。

### 5.9 新机器/重装后装一次钩子（每台机器各做一次）

`.git/hooks` 不入仓，重装后 pre-commit 的双写校验与自动导快照会静默缺席：

```bash
cp ~/.redcode/scripts/hooks/pre-commit ~/.redcode/.git/hooks/pre-commit && chmod +x ~/.redcode/.git/hooks/pre-commit
```

## 6. 索引层审计（260910 起）

**和整理不是一回事**：整理是条内压缩 + 归类（5.x，条数不减）；审计是**淘汰索引行**——全文留在库里，只是不再进每轮注入面。索引层是「每轮可见名单」，不是记忆本身，所以删索引行**可逆**：靠 FTS 照样召回（260910 实测 #157-160 删掉索引行后仍被 `/recall` 命中）。

判据：逐条问 **「它需要每轮被看见吗？」**

| 类别                                                                     | 处置                                                                                                                                                |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 与 AGENTS.md / system prompt / skill **重复**                            | 删索引行——规则面已覆盖，且往往写得更细                                                                                                              |
| **机制已拦**（权限请求、hook、强制校验）                                 | 删——记忆买不到额外安全，拦得住的是"结果"，最终决定权在用户手里                                                                                      |
| **过时**（依赖的能力/系统已变，如 PS5.1 的坑、已删的 UI）                | 删                                                                                                                                                  |
| **常识**（语言/框架的基本事实，如 DOM 属性是驼峰）                       | 删                                                                                                                                                  |
| **冷档案**（特定库的 API 坑、别个项目的技术栈）                          | 删索引行、靠召回——关键词（openpyxl / PyMuPDF / koffi）命中率很高                                                                                    |
| 安全类、高频工作纪律、项目关键路径                                       | **留**——这些才是"每轮在场"买得到的东西                                                                                                              |
| **模型缺陷补丁**（当年为弱模型写的提醒，如"别顺手扩大范围""别过度自信"） | 删——约束的对象（模型）已进化，提醒退化成噪音。**判据：这条约束的是环境，还是我的能力？** 约束环境（语言/工具/平台事实）的留；约束能力的复核，倾向删 |

**「模型缺陷补丁」要单独说**（260917 加）：记忆里有一类条目不是关于系统的，而是关于**我当年容易犯的错**——"别顺手扩大范围""别过度自信""为一个症状叠第二个补丁"。这类条目的保质期跟模型版本绑定：约束的**环境**不会变（语言、工具、平台、领域事实，永远该守），约束的**能力**会变（对象正在变强）。复核时问一句 **「这是环境事实，还是我的行为矫正？」**——前者留，后者倾向删。例：`hashline insert 不跟缩进` 是工具的坑（留），"提交前别忘记跑测试"是行为矫正（删）。

**核对纪律（血的）**：只凭索引行缩写判断会误判。260910 第一次审计就错了 4 条——#105 实际是「rg **装了**但 agent 环境 PATH 里没有」，跟缩写写的正好相反；#2 与 #135 场景不同（一个说杀树、一个说别带 `/T`）不是重复；#74 是 `node -e` 引号坑，PS7 下同样成立。**动手前把待删条目全文批量拉出来看**（一条 SQL 全拿），再定。

**验证**：`bun ~/.redcode/scripts/check-memory-dualwrite.mjs`——orphan 数会涨（就是被淘汰的那些），**提示不阻断**；要盯的是"索引行全部有全文"仍 ✅。再前后对比字符数。**唯一不变量**：剩下的索引行都有全文 + 库行数不减。

## 归档目录 `~/.redcode/memory/`（已退役，只读）

`YYMMDD.md` 每日日志与 `INDEX.md` 会话索引**不再写入**。退役原因（2026-07-29 实测）：它们不注入、要模型主动去读，而近 14 天 113 个会话里开局读过 `INDEX.md` 的只有 1 个（0.9%）；同期唯一的自动写入者是个低精度正则分类器（把"还有什么**可以**优化的"记成"被表扬"）。既没人读也写不准，且与项目记忆高度重复。

保留可查。翻旧账：查库（`sqlite_query`）或 grep `memory/lessons-backup.<机器名>.md`（库的可读快照，入库推送，是全文版本化与跨机可见的唯一通路）；`/recall <关键词>` 命令走 `supermemory.db`——默认搜 global + 当前项目，`--all` 搜全库（260910 起，此前解析 MEMORY.md 的版本已随索引化失效）。**归档文件不在召回范围内**，`REDCODE_MEMORY` 不再指向它。

## 工具红线

- **整理用 `write` 全量重写是对的**——前提是 5.1 已完整 read 过。只有"局部追加"才禁用 write
- **绝不用 bash `echo >>`**：Windows 上中文变 GBK 乱码，`redline-guard` 会拦
- **绝不用 PowerShell `Set-Content`**：写 BOM
