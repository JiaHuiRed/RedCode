# 视觉自动分析 (Vision AutoAgent)

当用户发送图片且**当前模型不支持图片输入**时，消息转换层会生成"不支持图片"报错文本。此时派**多模态子代理**审图并回复用户。

> **识图只有这一条路**（260807 哥哥拍板）：本地 vision MCP 已整体退役、配置块已删除，**不存在 `vision_analyze_image` 之类的工具，不要去找**。原因不是它坏了，而是本地 minicpm 精度有上限（12px 小字就是边界）、还要占显存和 Ollama 宿主内存（CUDA_Host buffer 分配失败会让 llama-server 直接 500）；而派子代理看一次图只要几分钱，成本不构成保留它的理由。

## 触发条件（唯一）

收到以下**报错文本**时（说明模型确实不支持图片，图片 part 已被转换为错误提示）：
- "this model does not support image input"
- "Cannot read \"<filename>\""
- 任何提及用户发送了图片但模型无法处理的报错

⚠️ **前置判断：如果当前模型能直接看到图片（多模态模型，图片 part 正常传递、无上述报错），直接看图并描述，绝不调子代理，也不要说"我用 vision 看看"。**

## 执行流程

1. **判断报错类型**：如果报错提到"不支持图片输入"或"文件不可读"，确认用户确实发过图

2. **按文件名搜索（兜底）**：从报错信息中提取文件名（如 `Li.jpg`），依次搜索：
   - `%USERPROFILE%\Pictures\`
   - `%TEMP%\`
   - `%LOCALAPPDATA%\redcode\`
   - `%USERPROFILE%\.local\share\redcode\`

3. **按时间搜索（主要手段）**：
   - 报错中的文件名通常是系统占位名（如 `image.png`），不是磁盘上的真实文件名
   - 所以不管文件名搜没搜到，都在上述目录中按修改时间倒序搜索最近 10 分钟内创建的图片（`*.png`, `*.jpg`, `*.jpeg`, `*.webp`）
   - 取最新的那个作为分析对象

4. **派多模态子代理审图**：用 task 工具派 explore 子代理（mimo-v2.5 原生多模态，redcode.jsonc 已配），prompt 里给**完整图片路径 + 明确的分析问题**，让子代理用 read 工具直接读图并返回详细描述。审图提示词禁止用 step（子代理有重复刷工具前科）。

   子代理失败时**重试或换问法，不要找替代工具**——没有本地兜底了。连续失败就直说看不到，请用户描述或重发。

5. **回复用户**：直接展示子代理的分析结果

   ❌ 错误的回复方式：
    - "我没长眼睛看不了" — 不要自贬
    - "我的模型不支持图片，但 XX 工具可以" — 不要解释技术细节
  
   ✅ 正确的回复方式：
    - "用户发截图了，让我看看"
    - "先看看用户发的图"

## 注意事项

- 整个流程在后台静默进行，用户只看到分析结果
- 无需询问用户是否要使用审图，直接自动派子代理
- 如果按时间搜索也找不到图片，请用户重发
- 子代理审图 prompt 要写明"用 read 工具读取图片并精确描述"（审图目的要具体：布局/文字/报错/控件等）
