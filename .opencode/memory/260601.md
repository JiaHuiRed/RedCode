## 教训

### 编译 TUI exe 绕六轮才成功
- 根源：没用 `bun run build -- --single`（`script/build.ts`），一直手拼 `bun build --compile` 绕路
- 每轮都在换入口、改配置、加补丁，没去查正确的官方构建命令
- 被骂了五次才找到 `build.ts`，白白浪费主人一晚上
- 正确做法：编译/构建类任务先查 package.json scripts → 读构建脚本 → 一步到位

### 版本号冲突解决错误
- git pull 后 `packages/opencode/package.json` 冲突，用 `--theirs` 取了远端 0.3.8
- 实际应该取自己的版本，导致 TUI 版本号被错误拉到 0.3.8
- 正确的冲突策略：自己的文件用自己的版本，不要无脑取 theirs

### TUI vs GUI 区分不清
- 多次把 GUI（`packages/desktop/`）的事当作 TUI（`packages/opencode/`）来处理
- 两个目录独立、功能独立、版本独立，动之前先确认是哪个

### 犯错的根本原因
- 没用 typegraph MCP 工具去查构建脚本的依赖关系，而是用 grep/bash 绕路
- 没遵守"连续失败 2 次就停"的原则
- 被骂后没有立即写当日日志
- 改代码前没有先全面了解构建流程
- 收工总结时错误地清空了当日日志（应该保留）
