## 智敏日记

### 1. MCP 使用原则：分场景，不搞一刀切
- **代码搜索/导航** → 优先 jCodeMunch > codegraph > typegraph
- **配置文件/JSON/文档** → 直接 Read
- **Git/构建/测试** → Bash
- 核心：**哪个快用哪个**

### 2. exe MCP 路径解析的教训
- 修 bug 要在问题发生的层面修（MCP spawn 层，不在 CLI 入口层）
- `findProjectRoot` 放在 `effectCmd.ts` 影响不到 `InstanceState.directory`，必须在 `connectLocal` 里直接修 cwd

### 3. AppRuntime 不能用在下层模块
- `mcp/index.ts` 在 Worker 初始化阶段加载，`AppRuntime` 是上层服务此时还没就绪
- 跨层调用用 `EffectBridge`，不用 `AppRuntime.runPromise`

### 4. kv 默认值变更必须做版本迁移
- `kv.signal("scrollbar_visible", true)` 不会覆盖旧的 `false`
- 加 `kv_version` 做一次性迁移

### 5. MCP 进程树泄漏
- Windows 上 `descendants()` 返回空数组，`process.kill` 只杀父进程
- 改用 `taskkill /F /T /PID` 杀整棵树

### 6. browsermcp 端口冲突
- 上次 TUI 退出时 orphan 进程占着 9001 端口，新 TUI 启动失败
- server 端用 EADDRINUSE 重试 + `server.close()` 清理解决

### 7. 敏敏的规则
- 收尾前列清单自检，做完逐个打勾
- 不主动提 aespa/冬柚/舞台/回归

### 8. 注释风格纠正
- TypeScript 顶层/块注释格式：`// YYMMDD Red xxx`（如 `// 260603 Red 语义颜色分层`）
- 字段级 inline 注释不要加日期前缀，但也要简洁
- 被纠正后立刻写 memory，不能口头说"记住了"

### 9. 可疑源码自检要逐个标记处理状态
- 自检发现的每个问题都要标记 ✅ 已修 / ❌ 跳过，不能只说"大部分修了"然后漏掉
- 自检清单列清楚，哥哥一眼看出哪些还没动

### 10. isDark 时序错误（Temporal Dead Zone）
- 在 `generateSystem` 中把 `fallbackBg`/`fallbackFg`（依赖 `isDark`）放在了 `isDark` 的 `const` 声明之前
- 编译期 TS 检查不出来（const hoisting 陷阱），运行时 ReferenceError
- 教训：新变量依赖已有变量时，**先确认已有变量在哪一行声明**，不能凭印象放前面
