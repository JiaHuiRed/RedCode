### 1. 标题栏版本号写死漂移（0.3.17 根治）
`index.html` 标题栏徽章一直硬编码 `v0.3.16`，每次升级靠手改、漏改就编出旧版号。改成占位符 `__RC_VERSION__`，`electron.vite.config.ts` 加 `redcode:inject-version` 插件 build/dev 时从 `package.json` 注入。教训：能从单一来源自动注入的，绝不留第二处手填。

### 2. EBUSY 构建坑——查了半天竟是自己挖的
desktop bat 打包时 `afterAllArtifactBuild` 把 `win-unpacked` 改名 `win` 反复 `EBUSY: rmdir dist\win`，静默 catch 还照打 "Done"，留下旧 0.3.15。`tasklist` 没抓到 RedCode/node 进程，一度怀疑 Defender。真相：**有进程把空目录当 CWD（当前工作目录）就会让 rmdir 报 busy**——是调试时从 `dist\win` 启动 exe 留下的几个卡死 shell，CWD 钉在那。教训：①重建前先关掉从输出目录启动的 exe、排查 cd 进去的僵尸 shell；②查目录锁用读 PEB CurrentDirectory 扫所有进程 CWD（`NtQueryInformationProcess`），比猜进程名靠谱；③静默 catch 是帮凶，构建失败必须 throw 报错，别假装 Done。

### 3. bat 编码坑
`Write` 工具存 UTF-8，但 cmd.exe 按系统 OEM 码页（中文机 GBK）读 `.bat`，中文 `rem` 注释字节被打乱，连累 `rem`/`copy`/`exit` 整行解析错。教训：**bat 注释一律纯 ASCII/英文**，跨机/git 回家都不炸。

### 4. 通知图标死域名

### 9. 拍板 kimi-k2.5 没验证 → ProviderModelNotFoundError（教训 #）
**错**：`/goal` 命令 YAML 里写 `model: kimi-k2.5`，理由"想轻量执行"。TUI 后端 `SessionPrompt.getModel` 找不到 kimi → `ProviderModelNotFoundError` → GUI 端 toast "发送命令失败 — Unexpected server error"。
**根因**：①没问哥哥 kimi 是否配过（哥哥"从来没配过"）；②没查 provider 列表（`~/.redcode/config` / `~/.config/opencode/redcode.jsonc` / GUI 端 `app.getPath("userData")`）；③自己脑补"轻量 = kimi"。

### 10. 命令文件位置：`.opencode/command/` vs `~/.redcode/command/`
**机制**：TUI 引擎扫 `~/.redcode/command/**/*.md`（**不扫** `.opencode/command/`）。sync-home.bat 把 `.opencode/command/*` 复制到 `~/.redcode/command/*`（敏敏 2572cff12 补的）。所以**编辑时改 `.opencode/command/`（进仓库）**，**build 后**才到 home。改完想立即测：**手动 Copy-Item** 复制到 `~/.redcode/command/` 绕过 build。

### 11. GUI 端"发送命令失败"错误链
`submit.ts:481-487` 的 catch 把 err 喂 `formatServerError` → "Unexpected server error. Check server logs for details." → **真错在 TUI 后端日志** `~/.local/share/redcode/log/`，不在 GUI 端。查 GUI 端问题前**先 grep 后端日志**错误堆栈。

### 12. write 工具覆盖 260604.md 灾难（自检 #）
收工总结时用 `write` 工具写日志，**直接覆盖**了 48 行完整文件（雨琦 1-8 + 智敏 1-6），丢了一整天的工作记录。`write` 描述明说"will overwrite"——我没先 `read` 现有内容。**教训**：①**日志文件用 `edit` append，绝不 `write`**；②任何 `write` 前**先 read** 确认不会丢东西；③ `write` 之前先问"我是不是要 overwrite"。

新增 `simplify` skill（识别过度工程、把代码改回刚好够用）。落点 = 仓库 staging `.opencode/skill/<name>/SKILL.md` + build.bat 同步到 `~/.redcode/skill/`。理由：home `~/.redcode` 被引擎**无条件扫描**=每项目每台机器都加载，是唯一真普适载体；放仓库 `.redcode/skill/` 只在本仓库内被 up-walk 扫到、出仓库失效且和 home 镜像双重加载。教训：跨机能力放 home hub，别放项目目录。

### 4. 斜杠命令从未实装——`.opencode/command` 引擎不扫
