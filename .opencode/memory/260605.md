### 0.4.2 黑屏——可疑排查区域（给敏敏/下周，按优先级，一刀一刀切）

已锁定的硬事实（别再重复验证）：① 打包版 Console 零 JS 报错→**非崩溃**；② dev 能渲染、打包不能→差异在**运行环境而非源码**；③ 整片空连 composer 都没→是某个**高层 `<Show>` 的 when 条件在打包下永不为真**（数据没到），不是 messagesReady 那层（那层只盖 timeline，不盖 composer）。

**排查 1（最高优先，一刀定生死）= 打包版 Network 标签看本地 sidecar 通不通**
- 打开 RedCode Dev.exe → DevTools → Network → 进会话复现 → 看有没有发往本地 sidecar 的请求（`http://127.0.0.1:<port>` 或 localhost），重点 `/event`(SSE 流)、`/session`、`/app`、message/agent 相关端点。
- 判读：**全是 `ERR_CONNECTION_REFUSED`/pending** → sidecar 没起来（转排查 2）；**请求 200 有数据但界面仍空** → sidecar 好，是渲染层数据消费/门控问题（转排查 4）。这一步把问题树砍掉一半。

**排查 2 = 主进程 spawn sidecar 的代码（打包 vs dev 路径分叉）**
- 在 `packages/desktop` 主进程侧搜 `spawn`/`execFile`/`fork`/`sidecar`/`opencode`/`127.0.0.1`/`server`，找它怎么起后端。
- 关键对比：**dev 起 predev 现编 sidecar**（链好）；**打包起打进包的产物**。`packages/opencode/dist/` 下有两套：`node/`(16:44 新) 与 `redcode-windows-x64/`(09:11 旧)。**确认打包版到底 spawn 哪一套**——若指向 `redcode-windows-x64` 单 exe 而它是旧的(09:11)、与 0.4.2 渲染层契约不符，就是它。
- 看主进程日志：sidecar 进程是否成功 spawn、是否秒退/崩溃、报什么。app.asar 里 sidecar 路径打包后是否解析正确（常见坑：要 spawn 的二进制被打进 asar 取不到，需 asarUnpack/extraResources）。

**排查 3 = 打包流水线是否把对的 sidecar 嵌进去了**
- `electron-builder.config.ts` 的 files/extraResources/asarUnpack：sidecar 产物有没有被正确收进 `resources/`。本次打包 `resources/` 只见 `app.asar`+`app.asar.unpacked`+`icons`，**没单独 sidecar 目录**——确认 sidecar 是塞进 app.asar 了还是漏了。
- 记忆坑：「desktop build 不重编 opencode，只打包现有 `packages/opencode/dist`」。若 dist 里被 spawn 的那套是旧/半成品，打包就带病。**这次该先重编 opencode 再打包对照**。

**排查 4（若排查 1 显示 sidecar 通但仍空）= 渲染层数据门控**
- `directory-sync.ts`：`tracked()`(305)=seen 是否含 sessionID；`loadMessages`(307) line 322 `if (!tracked()) return` **会丢弃已拉到的 messages**；`sync()`(420)→`touch()`(424) 才把 sessionID 加进 seen。打包下 touch 时序错位→消息拉到即弃→空。
- 找盖**整个会话面板**的那个 `<Show>`：composer 也没了，说明门控比 `session.tsx:222 messagesReady`(只盖 1550 的 MessageTimeline、composer 在 1593) 更高层。搜 session 页顶层 `<Show when=` / `local.ready()` / `sync.data.agent_ready` 在 render 路径的消费点——若某处把整页盖在 `ready()` 上、而打包下 sidecar 没喂数据致 ready 永假，就整页空。
- 注意：排查 4 的现象 dev 应同样出现却没有→反推**问题更可能在 sidecar 侧(排查 1/2)**，排查 4 仅作 sidecar 排除后的备选。

**最省力路线**：先做排查 1（Network 截图），结果直接决定走 2/3（sidecar 没起）还是 4（数据门控）。不要跳过 1 直接改代码。
